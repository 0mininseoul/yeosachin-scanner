# 체리 Threads 자동화 설계

## 운영 흐름

1. 기존 체리 운영 콘솔에 Threads 메뉴를 추가한다. 운영자는 하루치 소재를 전남친, 남친, 짝남 등 한 관계로 정한다. 새벽까지 이어지는 글은 전날 저녁과 같은 회차에 속한다.
2. AI가 해당 관계의 교정 사례와 이전 글에 달린 독자 반응을 읽고 초안을 작성한다. 운영자는 콘솔에서 본문, 첫 답글, 게시 시각을 검토하고 하루치를 묶어 승인한다. 게시 대상으로 잠근 문안과 초안을 구분한다. 승인 후 문안을 수정하면 새 버전은 검토 대기 상태로 돌아간다.
3. Supabase에 승인한 문안 버전과 예약 시각을 저장한다. Supabase Cron이 20분마다 데이터베이스에서 처리할 작업이 있는지 확인한다. 기한이 된 발행, 지표 조회, 초안 생성 또는 만료가 가까운 Meta 토큰 갱신 작업이 있을 때만 전용 인증으로 Vercel 워커를 호출한다.
4. Vercel 워커가 예약된 원글을 공식 Threads API로 발행한다. 제품 안내가 승인된 글은 원글 게시 ID를 받은 뒤 첫 답글을 발행한다. 서버가 Threads 게시와 성과 수집을 담당하므로 운영자의 Mac 전원과 독립적으로 돌아간다.

이 자동화는 Supabase와 Vercel로 운영한다. 운영 화면은 기존 관리자 인증을 활용한다. 게시 계정은 `@youlovecherry_` 하나로 제한하고, Meta 앱과 계정 연결 및 게시·답글·인사이트 권한을 운영 전 확인한다. [Supabase Cron](https://supabase.com/docs/guides/cron) · [Threads API](https://developers.facebook.com/documentation/threads)

## 20분 단위 편성

- 한국시간 매시 00분, 20분, 40분을 게시 슬롯으로 삼고, 저장 시각은 UTC로 기록한다. 기존 20~40분 간격을 유지할 때는 슬롯을 한 칸 또는 두 칸 건너뛴다. 실제 게시 시각에는 실행 지연이 더해질 수 있다.
- 한 계정에 한 슬롯당 원글 한 편만 배정한다. 여러 미처리 글이 쌓이면 다음 슬롯부터 한 편씩 처리한다. 회차 종료 시각을 지나면 콘솔에 재편성 필요로 표시한다.
- 24시간 운영 기준 조회 주기는 하루 72회다. 대기 작업은 예약 시각과 상태 인덱스로 찾는다. 새 예약, 수동 재시도, 정기 실행은 같은 작업 상태와 처리 잠금을 사용한다.
- 게시 성공 시 원글 ID와 실제 게시 시각을 저장한다. 첫 답글은 원글과 별도의 처리 상태를 갖고, 답글만 실패하면 저장된 원글 ID에 대한 답글만 재시도한다. 게시 요청의 결과가 불명확하면 Threads에서 발행 여부를 확인한 뒤 이어간다. 확인이 어려운 글은 운영자가 콘솔에서 점검할 수 있게 표시한다.

## ChatGPT Pro 크레딧으로 초안 생성

- 활성화된 Pro API 크레딧을 사용할 수 있으면, Vercel 서버가 연결된 API 조직의 프로젝트 키를 써서 OpenAI Responses API를 호출한다. 활성 상태가 7일 이상인 유료 Pro 구독과 동일 이메일의 API 조직 소유자 권한이 필요하다. 실제 계정의 크레딧 연결과 잔액은 아직 확인하지 않았다. [구독 연계 크레딧 공식 안내](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)
- 운영자가 콘솔에서 다음 회차 초안을 요청할 수 있다. 자동 작성이 켜진 날에는 검토 시간에 맞춰 하루치 초안 작업 하나를 등록한다. Cron의 작업 점검에 이 요청도 포함한다. 완성된 초안은 검토 목록에 들어간다.
- 초안 요청과 발행 작업은 독립적으로 처리한다. 초안 생성이 잔액 부족, 권한 오류 또는 모델 응답 오류로 중단되면 콘솔에 사유를 표시하고 지금까지 저장한 문안을 보존한다. 운영자는 기존 ChatGPT 로그인 기반 Codex CLI에서 만든 초안을 가져올 수 있다. 서버 기본 실행 경로가 확인되면 API 초안 생성은 Mac 전원과 독립적으로 돌아간다.
- OAuth는 체리 Threads 계정을 Meta 앱에 연결할 때 사용한다. OpenAI 프로젝트 키와 Meta 토큰은 서버의 비밀 저장소에서 관리한다. 모델은 생성할 문안과 참고 자료만 받고, 발행 자격 증명과 승인 기능은 서버 워커와 운영 콘솔에서 관리한다.

## 교정 이력과 성과 반영

- 편집 전후 문장, 이유, 관계 소재, 회차를 저장한다. 게시 후 삭제한 글에도 운영자가 이유를 기록할 수 있다. 첫 데이터로 기존 주석과 확정 문안을 가져온다.
- 다음 초안에는 사용자가 확정한 규칙과 소재가 비슷한 최근 교정 사례를 넣는다. 어떤 사례를 썼는지 콘솔에 표시한다. 한 회차 한 관계, 짝남이 먼저 같이 가자고 해줬으면 하는 마음, 셀카 스토리나 구글맵처럼 구체적인 장면이 초기 기준이다.
- 한 글에 적용된 교정은 관련 있는 다음 문안의 참고 사례로 쓴다. 여러 회차에 적용할 새 규칙은 근거가 된 교정과 함께 제안한다. 운영자가 확정하거나 이전 버전으로 되돌릴 수 있다.
- 실제 원글 게시 약 24시간 후 조회수, 확인 가능한 독자 답글 수, 측정 시각을 저장한다. 체리가 직접 단 첫 답글은 독자 집계에서 제외한다. 조회수와 독자 반응은 다음에 시험할 소재를 고르는 데 활용하고, 문체에는 운영자가 직접 교정한 사례를 우선 적용한다. [Threads 인사이트](https://developers.facebook.com/documentation/threads/insights)

## 첫 검증의 완료 조건

1. 체리 계정을 연결해 기존 게시물의 조회수와 확인 가능한 답글을 불러온다.
2. 교정 한 건을 저장하고, 같은 소재의 다음 초안에 교정 사례가 반영됐는지 콘솔에서 확인한다. 첫 초안 생성 경로는 Pro 연계 크레딧을 확인한 뒤 결정한다.
3. 별도로 승인한 글 한 편을 20분 슬롯에 예약하고, 저장한 문안과 실제 올라간 게시물을 대조한다. 승인한 첫 답글이 있으면 원글에 한 번만 달렸는지 확인한다.
4. 같은 슬롯과 작업을 중복 실행해도 원글은 한 번만 게시된다. 답글만 실패하면 원글을 유지하고 답글만 복구한다. 작업이 없는 시각에는 Vercel 워커를 호출하지 않는 것을 확인한다.

## 운영 연결과 실제 계정 검증

1. Pro 혜택을 연결한 API 조직의 프로젝트 키를 Vercel Production `CHERRY_OPENAI_API_KEY`에 저장한다. `CHERRY_OPENAI_MODEL`은 선택값이며 기본 모델은 `gpt-5-mini`다.
2. Meta Developers에서 Threads 사용 사례가 있는 앱을 준비한다. 체리 계정을 테스터로 연결하거나 운영에 필요한 권한을 승인받는다. Vercel Production에 `CHERRY_THREADS_APP_ID`, `CHERRY_THREADS_APP_SECRET`, `CHERRY_THREADS_REDIRECT_URI`를 저장한다. 리디렉션 URI는 운영 콘솔과 같은 HTTPS 호스트의 `/api/admin/cherry/threads/oauth`이며 Meta 앱의 허용 목록과 일치해야 한다.
3. 운영자가 관리하는 비밀 저장소를 통해 임의의 32바이트 키를 Base64로 인코딩해 `CHERRY_THREADS_TOKEN_KEY`에 저장한다. 전용 실행용 난수를 Vercel `CHERRY_THREADS_CRON_SECRET`과 Supabase Vault의 `cherry_threads_worker_secret`에 같은 값으로 저장한다. Vault의 `cherry_threads_worker_url`에는 운영 호스트의 전체 `/api/internal/cherry-threads` 주소를 저장한다.
4. 두 migration을 검토한 뒤 운영 표준 절차로 적용한다. `cron.job`에서 `cherry-threads-20m`의 일정과 활성 여부를 확인한다. 전용 실행 URL과 인증값은 Secret으로만 관리한다.
5. 체리 운영 콘솔의 Threads 화면에서 OAuth를 완료하고 기존 글을 가져온다. 초안을 만든 뒤 모바일 콘솔에서 문장과 교정 이유를 저장한다. 다음 회차에서 같은 관계를 골라 초안을 만들고, 생성에 전달한 교정 사례 항목과 실제 생성된 문안을 함께 검증한다.
6. `CHERRY_THREADS_PUBLISH_ENABLED=true`를 설정한 뒤 테스트 문안 한 편의 발행을 승인한다. 실제 원글 ID와 첫 답글 여부, 같은 슬롯 재실행 시 중복 여부를 확인한다. 게시가 끝나면 24시간 측정 작업까지 확인한다.
