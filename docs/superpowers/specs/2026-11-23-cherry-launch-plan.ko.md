# 체리(남친 맞팔 알리미) 구현 계획

2026년 11월 23일 · **확정**(같은 날 사용자 답변 반영) · [서비스 기획서](2026-11-18-namchin-mutual-alert-design.ko.md)를 구현 단위로 옮긴 문서

**12월 1일 오픈을 목표로 기존 저장소에 체리 전용 모듈과 워커를 만든다. Apify 유료 계정과 Vertex 예산은 판독기와 함께 쓰고, 판독기 몫을 남기는 규칙을 둔다.** [결정 1~5]는 11월 23일 사용자 답변으로 확정했다.

## 1. 확인한 사실과 기획서에서 바꿀 점

| 확인한 사실 | 제안 |
| --- | --- |
| Apify 유료 계정(`secondary`)은 월 한도 $25 중 $17.51을 썼고(11/22) 12/19에 초기화된다. 남은 $7.49는 1,500명 계정의 첫 목록 7건 분량이다. Starter는 한도를 $100까지만 올릴 수 있고, 전부 첫 목록에 써도 800명 계정 178건이다. | 12/1 전에 한도를 $100로 올리고 유료 60명 전후에 Scale($199)로 전환한다 **[결정 1]**. 결제 전에 남은 예산을 확인하고, 부족하면 청구하지 않고 대기로 받는다. 승인됨. **아래 검증 결과로 방향별 전체 수집이 되면서 Scale 전환 시점은 유료 약 30명으로 당겨진다(재확인 필요).** |
| 숫자가 바뀔 때마다 두 목록을 모두 다시 모으면, 한 달에 10일 바뀌는 계정의 청구액이 800명 16,820원, 1,500명 27,250원이다. | 바뀐 방향만 전체를 다시 모으고 1인 월 6,000건 안에서 속도를 조절해 **정액**으로 판다(앞쪽만 모으는 안은 검증에서 탈락). **정가 월 9,900원, 사전 예약자는 첫 결제일부터 1년간 4,900원**이다. 출시 후 등록자의 얼리버드 혜택은 나중에 정하므로 가격을 코드가 아닌 혜택 표에서 읽는다 **[결정 2]**. |
| 카카오 심사 기준은 신청형 반복 안내를 광고로 볼 수 있고, 할인 안내는 알림톡으로 보낼 수 없다. | 유료 서비스 이용 안내로 템플릿을 신청하고, 미승인·발송 실패 시 문자로 보낸다(건당 알림톡 13원, 문자 45원) **[결정 4]**. 카카오 비즈니스 채널·솔라피·발신번호가 모두 없는 상태라, 문자도 준비되지 않으면 이메일로 보낸다(구현자 판단). 출시 혜택 안내는 이메일로 보낸다. |
| 랜딩은 ‘자동 환불’과 ‘사전 예약자 먼저’를 약속한다. 기획서는 수동 환불, IR 전략은 동시 공개다. | 환불은 랜딩 약속에 맞춘다. **판매는 12/1에 모두에게 동시에 연다** **[결정 5]**. 랜딩의 ‘사전예약하는 300명에게만 먼저’, ‘사전 예약한 분께만 먼저 특별혜택가로 오픈’ 문구는 이 결정과 어긋나므로 바꿀 문구를 따로 확인받는다. |

- **순서 검증 결과(11/23, 비용 0원)**: 앞쪽 수집의 전제는 성립하지 않는다. 같은 계정을 80시간 동안 반복 수집한 기존 실행 20쌍을 비교하니 순서 상관이 0.38~0.69(최신순이면 1에 가까워야 함)였고, 매번 1명 안팎이 빠졌다가 다시 나타났다. 계정 1개의 자료라 일반화에는 한계가 있지만, 순서에 기대는 방식은 쓸 수 없다.
- **정액 손익 추정**(월 10일, 하루 한 방향 변화, 1달러 1,400원, 부가세와 수수료 8.69% 반영): 정가 9,900원은 800명 계정이 첫 달 약 +3,000원·이후 월 +3,800원, 1,500명 계정이 약 −1,100원·+400원이다. 사전 예약가 4,900원은 800명 계정이 약 −1,100원·−300원, 1,500명 계정이 약 −5,200원·−3,700원이다. 월 6,000건 상한 때문에 한 사람의 월 원가는 첫 목록을 빼고 약 6,300원을 넘지 않는다. 300명(평균 800명 계정)의 Apify 비용은 첫 목록 $168, 첫 30일 합계 약 $1,030이다.

## 2. 사용자 흐름과 감지 방식

- **흐름**: 아이디 확인(공개, 합계 1,500명 이하, 인증 배지 계정 제외) → 카카오 로그인(알림은 카카오 계정의 휴대폰 번호로만) → 요금과 감지 한계 동의 → 결제 → 첫 목록 저장(이때부터 30일) → 매일 확인 → 새 맞팔은 하루 1건으로 알림 → 리포트 → 내 서비스(상태·다음 결제·해지).
- **매일 확인**: 07시부터 숫자 확인 → 바뀐 방향의 목록 전체 수집 → 09시 발송. 숫자가 그대로여도 14일마다 다시 읽는다. 성별과 관계없이 알린다. 월 6,000건이 날짜에 비례해 쌓이므로 조용한 계정은 당일, 변화가 아주 잦거나 큰 계정은 2~4일에 한 번 모아 확인한다.
- **오알림 방지**: 목록에서 빠졌던 계정이 나중에 새 맞팔로 보일 수 있다. 계정 ID로 비교하고, 늘어난 숫자로 설명되는 계정만 확정으로 알린다. 빠졌던 계정이 섞였을 수 있으면 알림에는 넣되 리포트에 ‘예전부터 맞팔이었을 가능성’을 표시하고, 숫자가 늘지 않았는데 나타난 계정은 알리지 않고 내 서비스의 ‘나중에 보인 맞팔’에만 적는다. 사라진 계정은 두 번 이상, 14일 넘게 안 보일 때만 해제로 본다.
- **다시 확인받을 것**: 전체 수집으로 바뀐 손익에 맞춰 요금·상한·Scale 전환 시점을 다시 정한다.

## 4. 구조

- **같은 저장소의 독립 모듈(추천)**: 화면 `/cherry/*`, `lib/services/cherry/`, `cherry_*` 테이블(서버 전용 권한), 전용 Cloud Run 워커·스케줄러. 작업 대기열은 DB 표로 두고 1분마다 스케줄러가 깨우며, 아이디 확인처럼 바로 처리할 일만 Cloud Tasks로 앞당긴다. 수집기·카카오 로그인·이미지 저장·예산 원장은 재사용하고 판독기 분석 DAG는 건드리지 않는다. 판독기 파이프라인에 편입하면 잠금·장애를 함께 겪고, 별도 저장소는 공유 자원 연결을 새로 만들어야 해 12/1에 맞추기 어렵다.
- **결제 [결정 3]**: 토스 자동결제(위장여사친판독기로 신청했고 11/23 현재 미승인, 청구 스케줄러는 직접 구현). 11/28까지 미승인이면 그로블 30일 이용권(자동 갱신 없음)으로 열고 다음 회차에 전환한다. 사전 예약가는 카카오 번호나 이메일이 명단과 같을 때 자동 적용하고, 예약 1건은 회원 1명에게만 쓴다.
- **실패·환불**: 첫 목록이 24시간 안에 안 되면 안내하고 전액 취소를 고르게 한다. 비공개 전환은 감시·다음 결제를 자동 중지하고 남은 일수를 환불한다. 토스는 자동이고 그로블은 운영자가 처리하므로, 그로블로 열면 랜딩의 ‘자동 환불’ 문구를 바꿔야 한다.
- **운영**: 체리 콘솔에 구독·수집 실패·비용·발송·환불을 추가하고 판매·감시·AI를 각각 끌 수 있게 한다. 회원 탈퇴와 연동하고 사진은 30일, 목록·리포트는 해지 30일 후 삭제한다. 대상 계정의 등록 차단·삭제 요청도 처리한다. 법률 자문은 아직 요청하지 않았다. 회신이 오면 보관·고지를 조정한다.

| 컨펌, 외부 심사 신청, 목록 순서 검증 | DB·수집·비교·예산 규칙 | 가입·결제·리포트·알림·AI·콘솔 | 판매를 끈 채 배포, 실계정 검증 | 대기 마감·점검 → 오픈 |

- **완료 기준**: 본인 계정으로 결제 → 첫 목록 → 실제 새 맞팔 감지 → 카카오 또는 문자 수신 → 리포트 → 다음 회차 청구(또는 재구매) → 비공개 전환·환불까지 한 번 완주한다. 같은 변화의 중복 알림과 중복 청구가 0건이고 판독기의 기존 검사와 운영 경로가 그대로 통과한다.
- **컨펌하면 맡아서 진행**: 코드, PR·독립 리뷰·main 병합, 체리 DB migration, 판매를 끈 워커 배포, 약 $1 순서 검증. **따로 확인받고 진행**: Apify 요금제·한도, 실결제·환불, 사전 예약자 발송, 판매 시작, 랜딩·약관 문구.
- **오늘 사용자가 시작할 일**: ① Apify 한도 상향 ② 카카오 비즈니스 채널·솔라피·문자 발신번호 ③ 토스 자동결제 계약 문의와 그로블 상품 준비.
