# 체리(남친 맞팔 알리미) 구현 계획

2026년 11월 23일 · **확정**(같은 날 사용자 답변 반영) · [서비스 기획서](2026-11-18-namchin-mutual-alert-design.ko.md)를 구현 단위로 옮긴 문서

**12월 1일 오픈을 목표로 기존 저장소에 체리 전용 모듈과 워커를 만든다. Apify 유료 계정과 Vertex 예산은 판독기와 함께 쓰고, 판독기 몫을 남기는 규칙을 둔다.** [결정 1~5]는 11월 23일 사용자 답변으로 확정했다.

## 2. 사용자 흐름과 감지 방식

- **흐름**: 아이디 확인(공개 프로필 조회만. 합계 1,500명 이하, 인증 배지 계정 제외) → 카카오 로그인(알림은 카카오 계정의 휴대폰 번호로만) → 비공개 계정이면 인스타그램 로그인 연결과 팔로우 관계 확인(로그인한 회원에게 묶인 별도 요청으로만. 익명 아이디 확인은 IP·아이디 기준으로 재사용되므로 이용자 세션을 붙이지 않는다) → 요금과 감지 한계 동의 → 결제 → 첫 목록 저장(이때부터 30일) → 매일 확인 → 새 맞팔은 하루 1건으로 알림 → 리포트 → 내 서비스(상태·다음 결제·해지).
- **매일 확인**: 07시부터 숫자 확인 → 바뀐 방향의 목록 전체 수집 → 09시 발송. 숫자가 그대로여도 14일마다 다시 읽는다. 성별과 관계없이 알린다. 월 6,000건이 날짜에 비례해 쌓이므로 조용한 계정은 당일, 변화가 아주 잦거나 큰 계정은 2~4일에 한 번 모아 확인한다.
- **오알림 방지**: 목록에서 빠졌던 계정이 나중에 새 맞팔로 보일 수 있다. 계정 ID로 비교하고, 늘어난 숫자로 설명되는 계정만 확정으로 알린다. 빠졌던 계정이 섞였을 수 있으면 알림에는 넣되 리포트에 ‘예전부터 맞팔이었을 가능성’을 표시하고, 숫자가 늘지 않았는데 나타난 계정은 알리지 않고 내 서비스의 ‘나중에 보인 맞팔’에만 적는다. 사라진 계정은 두 번 이상, 14일 넘게 안 보일 때만 해제로 본다.
- **다시 확인받을 것**: 전체 수집으로 바뀐 손익에 맞춰 요금·상한·Scale 전환 시점을 다시 정한다.

### 비공개 계정 지원 (11/24 결정)

이용자가 팔로우 중인 비공개 계정은 이용자 본인 인스타그램 로그인으로 지원한다. 숫자 변화만 알리는 안(누구인지 모름)과 비교해, 누구인지까지 알려주는 쪽을 택했다. 랜딩과 FAQ는 같은 날 이 방향으로 바꿨다.

- **수집**: Apify 무쿠키 수집기는 비공개 목록을 읽지 못한다. 세션 기반 수집기 `services/instagram-auth-worker`를 버너 계정 대신 이용자 세션으로 돌린다. 지금은 목록 행에 계정 ID가 없고(`_user_row`) 한 방향 최대 1,200명(`RelationshipRequest.limit`)이라, 계정 ID를 함께 받도록 바꾸고 방향별 한도를 등록 조건(합계 1,500명 이하)에 맞추거나 결제 전에 방향별 한도를 적용한다. 프로필·팔로워·팔로잉 읽기만 허용하고 팔로우·좋아요·메시지·스토리 열람은 코드에서 막는다. 이용자 세션당 하루 확인 1회, 바뀐 방향만 수집한다.
- **로그인과 보관 (피클 방식 벤치마크)**: AI 에이전트 앱 [피클](https://pickle.com/)처럼 로그인을 클라우드 브라우저에서 처리한다.
  - 아이디·비밀번호는 채팅이나 일반 입력칸이 아닌 전용 보안 로그인 카드에서 받는다. 체리는 이 값을 AI 요약·로그·오류 보고·운영 콘솔 어디에도 넘기지 않는다.
  - 로그인은 매번 새로 여는 클라우드 브라우저(실제 Chromium, 국내 고정 IP)에서 한다. 이용자별로는 기기 정보(브라우저 종류·화면·언어)만 고정해 새 기기 로그인을 줄이고, 로그인 상태가 담긴 프로필은 디스크에 남기지 않는다. 로그인 확인·캡차가 나오면 그 브라우저 화면을 이용자에게 그대로 보여 주고 직접 풀게 한 뒤 ‘다 했어요’로 이어간다. 문자·이메일 인증번호는 카드에 입력받는다.
  - 비밀번호와 세션 쿠키는 Supabase Vault에만 암호화해 저장하고 `cherry_*` 표에는 비밀 ID만 둔다. 피클은 이용자 휴대폰에 보관하지만, 체리는 이용자가 앱을 열지 않아도 매일 확인해야 하므로 서버에 둔다. 복호화는 워커의 서버 전용 함수에서만 한다. 2단계 인증 비밀키는 받지 않는다. 비밀번호와 함께 있으면 두 인증 수단이 한 권한에 묶이므로, 2단계 인증이 필요하면 이용자가 그때 코드를 넣는다.
  - 비밀번호 안내는 피클처럼 범위를 나눠 말한다(11/25 결정). 랜딩·동의문은 ‘Vault로 바로 들어가고, 비밀번호는 인스타그램 로그인 때만·세션은 매일 확인 때만 풀리며, 운영자 화면과 기록에는 나오지 않고, 연결을 끊으면 바로 삭제된다’까지만 약속한다. 삭제 후 DB 백업 보존 기간 동안 남는 사본의 처리(백업 보존 기간 안내 또는 비밀만 별도 키로 암호화해 키 삭제로 무효화)는 구현 때 정한다. 이를 지키려고 운영 콘솔·로그·오류 보고·AI 입력에 비밀번호·세션이 나오지 않음을 검증하고, 복호화할 때마다 일시·목적을 기록한다. ‘체리 팀도 꺼낼 수 없다’는 Confidential Space처럼 검증된 코드 안에서만 키가 풀리는 봉인 구조를 만든 뒤에만 쓴다(B안, 미정).
  - 매일 확인은 Vault의 세션 쿠키만 써서 브라우저 없이 처리한다. 재로그인 때만 브라우저를 열어 Vault의 쿠키를 넣고, 끝나면 갱신된 쿠키를 Vault로만 돌려놓은 뒤 브라우저 데이터를 지운다. 브라우저 종료 후 디스크·스냅샷에 로그인 상태가 남지 않는지 검증한다.
  - 연결 해제·이용 기간 종료·탈퇴 시 Vault 값을 지우고, 인스타그램에서도 로그아웃한다. 피클은 해제 후에도 사이트 로그인 상태가 남아 이용자가 직접 기기 목록을 정리해야 했다.
  - 내 서비스 화면에 ‘체리가 내 계정으로 한 일’ 기록(날짜별 읽기 횟수, 쓰기 0회)을 보여 준다. 피클의 접근 기록처럼 ‘읽기만 해요’를 이용자가 직접 확인하게 한다.
  - 읽는 범위는 등록한 대상 1명의 프로필·팔로워·팔로잉으로 묶는다. 피클은 연결 직후 다른 서비스 내용을 넓게 읽어 지적을 받았다.
- **끊김 처리**: 세션 만료면 저장한 비밀번호로 다시 로그인한다. 로그인 확인 요구·비밀번호 변경·팔로워에서 제외됨이면 알림을 멈추고 이용자에게 다시 연결해 달라고 안내한다. 접근을 잃은 즉시 다음 회차 청구를 보류하고 그 시각을 환불 기준으로 기록한다. 7일은 재연결 기한으로만 쓰고, 그 안에 복구되지 않으면 감시를 중지하고 접근을 잃은 시각부터 남은 일수를 환불한다(제안).
- **위험 고지**: 연결 전에 이용자 계정이 로그인 확인을 요구받거나 일시 제한될 수 있고, 이용자에게 새 기기 로그인 알림이 올 수 있다는 점을 안내하고 별도로 동의받는다. 대상 계정에는 아무 알림도 가지 않는다. 인스타그램 약관은 자동화 접근을 제한하고, 플랫폼이 막으면 기능이 멈출 수 있다(피클의 카카오톡 연동은 카카오의 문제 제기 뒤 하루 만에 중단됐다). 이 경우 비공개 계정 이용자는 남은 일수를 환불한다.
- **비용·인프라**: 비공개 목록 수집에는 Apify 비용이 들지 않는다. 대신 로그인용 클라우드 브라우저 실행과, 로그인·수집을 같은 국내 IP에서 하기 위한 고정 프록시 비용이 든다(미정). 브라우저 실행은 로그인·재로그인 때만 하고 매일 확인은 세션으로 가볍게 처리한다.
- **미결**: 12/1 오픈에 포함할지. 포함하지 않으면 오픈 시 비공개 계정은 ‘곧 지원’으로 안내해야 한다. 개인정보처리방침은 11/24에 반영했다. 이용약관 제6조 제4항(체리 비공개 연결 예외, 공고 11/25·시행 12/2)과 비공개 연결 전용 동의문(`CHERRY_PRIVATE_CONNECTION_CONSENTS`, 개인정보 수집·이용과 계정 위험 확인 2개)은 11/25에 만들었다. 결제 동의문(`CHERRY_CONSENTS`)은 공개 계정 기준 그대로 두고, 비공개 대상일 때 카카오 로그인 뒤 연결 단계에서 전용 동의를 따로 받는다. 비공개 계정은 등록하려 할 때 그 화면에서 로그인 연결을 안내한다(랜딩 이용 방법에서는 뺐다). 약관 시행일이 12/2이므로 공개 계정 판매를 12/1에 열더라도 비공개 계정의 첫 연결·조회는 12/2 이후에만 허용한다.

## 4. 구조

- **같은 저장소의 독립 모듈(추천)**: 화면 `/cherry/*`, `lib/services/cherry/`, `cherry_*` 테이블(서버 전용 권한), 전용 Cloud Run 워커·스케줄러. 작업 대기열은 DB 표로 두고 1분마다 스케줄러가 깨우며, 아이디 확인처럼 바로 처리할 일만 Cloud Tasks로 앞당긴다. 수집기·카카오 로그인·이미지 저장·예산 원장은 재사용하고 판독기 분석 DAG는 건드리지 않는다. 판독기 파이프라인에 편입하면 잠금·장애를 함께 겪고, 별도 저장소는 공유 자원 연결을 새로 만들어야 해 12/1에 맞추기 어렵다.
- **결제 [결정 3]**: 토스 자동결제(위장여사친판독기로 신청했고 11/23 현재 미승인, 청구 스케줄러는 직접 구현). 11/28까지 미승인이면 그로블 30일 이용권(자동 갱신 없음)으로 열고 다음 회차에 전환한다. 사전 예약가는 카카오 번호나 이메일이 명단과 같을 때 자동 적용하고, 예약 1건은 회원 1명에게만 쓴다.
- **실패·환불**: 첫 목록이 24시간 안에 안 되면 안내하고 전액 취소를 고르게 한다. 공개 계정이 비공개로 바뀌면 인스타그램 로그인 연결을 먼저 안내하고, 연결할 수 없거나 이용자가 팔로우 중이 아니면 감시·다음 결제를 자동 중지하고 남은 일수를 환불한다. 토스는 자동이고 그로블은 운영자가 처리하므로, 그로블로 열면 랜딩의 ‘자동 환불’ 문구를 바꿔야 한다.
- **운영**: 체리 콘솔에 구독·수집 실패·비용·발송·환불을 추가하고 판매·감시·AI를 각각 끌 수 있게 한다. 회원 탈퇴와 연동하고 사진은 30일, 목록·리포트는 해지 30일 후 삭제한다. 대상 계정의 등록 차단·삭제 요청도 처리한다. 법률 자문은 아직 요청하지 않았다. 회신이 오면 보관·고지를 조정한다.
