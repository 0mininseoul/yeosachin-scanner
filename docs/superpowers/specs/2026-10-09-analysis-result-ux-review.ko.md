## 선택과 함께 승인할 공통 최소 개선

1. **수집 범위와 데이터 검증:** 기존 V2 DTO의 `declared`, `collected`, `coverageRatio`, `meetsCoverageGate`, `exactCountMatch`를 보존한다. 초기 결과와 페이지 이동 응답을 기존 runtime schema로 검증한 후 화면에 연결한다. 누락·불일치·gate 미달을 완전 수집으로 추정하지 않는다.
2. **정확한 상태 안내:** `collected < declared`가 하나라도 있으면 부분 수집을 표시한다. `collected > declared`는 수량 불일치로 구분하고, 비율 상한 100%로 exact=false를 숨기지 않는다. 현재 부분 fixture는 317/320와 297/300이며 99% 수집 기준을 통과하지만 정확한 수는 일치하지 않는다. 99%를 정확도·성별 신뢰도·전체 판독률로 표현하지 않는다. 양쪽 수량 일치만으로 공개 계정 전체 판독도 보장하지 않으므로 판독된 공개 계정 범위를 별도로 유지한다. 최초 개선에서는 비율·부분/불일치 상태와 범위 안내를 우선하고 상세 원시 수집 행을 표시하지 않는다.
3. **점수 의미:** 기존 점수·순위·등급 계산은 그대로 사용한다. `%`를 유지하면 “위험 지표”와 “분석 점수의 환산값이며 실제 발생 확률이 아닙니다”라는 설명을 제공한다. 값이나 계산 정책을 바꾸지 않는다.
4. **관리자 대비:** 기존 밝은 관리자 콘솔 안의 Dev 영역에 어두운 글자 토큰을 한정 적용해 대상·상태·상세를 읽을 수 있게 한다. 사용자 결과 화면 전체의 테마 재설계로 확대하지 않는다.
5. **Dev 상태 이름과 복귀:** 모의 결제 상태·합성 실행 상태·선택 시나리오를 명시적인 이름으로 분리하고 실행 상태는 한국어로 표시한다. 권한 거절에는 안전한 홈/로그인 복귀 행동을 제공한다. 실제 권한을 넓히거나 사용자 식별자·주문 식별자를 화면에 추가하지 않는다.

## 구현 범위와 고정 제약

선택한 결과 화면의 정보 순서·행 밀도·펼치기 행동·점수 설명을 기존 Next/React 화면에 구현한다. 데이터는 기존 응답의 공개된 owner 필드와 설명을 사용한다. 새로운 좋아요 수·대화 내용·성별 추론·근거 사진·예측을 만들지 않는다. 합성 모드의 프로필 행동은 내부 미리보기, Production의 기존 허용된 외부 프로필 행동은 기존 capability 계약을 유지한다. 공개/비공개 탭·페이지 이동·뒤로/새로고침·보관함·오류 복구는 동작해야 한다.

`app/page.tsx`의 확정 마케팅 카피, 점수 계산, 결제 가격·주문 상태, 소유자 권한, Dev allowlist, DB schema·이력, provider 및 worker 계약은 이 UI 승인으로 변경하지 않는다. Apify·AI·실제 카드 과금은 Dev에서 0회다. 실제 계정 분석은 사용자 실행 경계, Vertex 실측은 별도 예산 승인 경계를 유지한다. root `.env.local`·`.playwright-mcp/`·보호 migration·보존 refs/stash는 보존한다.

새 경로/DB/추가 유료 서비스나 장기 dev 브랜치를 만들지 않는다. 후보는 기존 `codex/*` PR에서 관련 검사·구현자와 다른 agent의 명세/품질 리뷰·Dev 실제 확인 후 main에 병합하고 root main/origin/main을 동기화한다. 직접 main push, 운영 재활성화, history repair/include-all은 하지 않는다. Dev 성공은 운영 결제사·실제 provider/AI 품질 성공의 증거가 아니다.

## 수용 기준과 미결 사항

- 선택한 생성 이미지의 구조와 현재 브랜드를 유지하며, 390×844 모바일과 데스크톱에서 가로 넘침·글자 잘림·중요 CTA 겹침이 없다. 긴 실제 프로필 이름도 줄바꿈/축약 규칙으로 처리한다.
- 본문은 읽을 수 있는 크기·대비로 표시하고, 중요한 눌림 영역은 최소 44px를 목표로 검증한다. 시안의 색과 대비는 구현 후 실제 computed style로 확인한다. 이미지 감상만으로 WCAG 전체 준수를 선언하지 않는다.
- complete·partial·empty·failed·잘못된 응답·페이지 이동을 기존 기능 검사에서 확인하고, DTO 오류·부분 수집이 완전 성공으로 보이지 않는다.
- 펼치기/탭/페이지/프로필/복귀를 키보드로 사용할 수 있고 focus가 보이며, modal을 열고 닫은 뒤 focus가 복구된다. 모바일 실물 기기와 스크린리더 전체 검증은 별도 미검증 경계로 남기면 명시한다.
- 관리자 목록과 상세의 실제 글자 대비, Dev 상태 구분, 권한 거절의 복귀를 Aside에서 확인한다. 계정 식별자·token·cookie·원시 행을 캡처/기록하지 않는다.
- 새 UI runtime이 바뀌면 새 Dev 후보를 배포하고 영향을 받는 실제 화면을 재검증한다. 코드 검사·독립 리뷰·exact-head CI를 통과한 변경만 PR로 main에 반영한다.

미결은 **시안 1/2/3 중 선택 또는 수정 요청**이다. 여러 시안의 일부를 조합하거나 추가 수정하면 먼저 수정 시안을 보여준 뒤 구현한다. 플랜 화면의 큰 구조 변경은 이번 결과 시안 선택 범위에 포함하지 않는다. 별도 사용자 요청 또는 실제 모바일 검증에서 드러난 명확한 문제를 근거로 다음 제안에서 다룬다.
