## 세 시안 비교

세 안 모두 검정·혈색 빨강·격자·기존 브랜드와 세 작업명을 유지한다. 두 작업이 동시에 “진행 중”일 수 있는 표현이다. **1안은 기존 원형 구조와 가장 가까워 우선 권고**하며 최종 선택은 사용자에게 있다.

| 안 | 구성과 장점 | 선택 시 확인할 점 |
| --- | --- | --- |
| 1 | 큰 원형에 “전체 진행률”을 명시하고 현재 활동·세 작업·보관함을 정리한다. 기존 화면을 유지하면서 수치 의미를 분명히 하기 쉽다. | 큰 원형이 세로 공간을 많이 사용하므로 좁은 화면에서 활동 설명과 다음 행동의 배치를 확인한다. |
| 2 | 현재 활동 설명을 먼저 보이고 전체 %·가로 바로 연결한다. 현재 무엇을 하는지와 전체 값을 빠르게 읽기 쉽다. | 기존 원형의 인상이 바뀌고 큰 제목이 높이를 차지한다. 강조한 빨간 보관함 CTA가 진행 정보보다 과하게 두드러지지 않도록 확인한다. |
| 3 | 작은 원형과 상단 상태, 별도 현재 활동 영역을 둔다. 전체 상태와 현재 프로필을 구분하기 쉽다. | 상단과 현재 활동에 정보가 나뉘므로 좁은 화면의 읽는 순서와 반복 설명을 확인한다. |

## 선택한 안에 적용할 공통 요구

1. **전체와 작업을 구분한다.** 원형 또는 가로 바에는 “전체 진행률”과 전체 %를 표시한다. “맞팔·AI 판독 / 위험 단서 수집 / 위험도·총평 정리”의 기존 상태는 유지한다. 병렬 작업을 순차 단계로 바꾸거나 선택 시안 때문에 계산을 변경하지 않는다.
2. **현재 활동은 데이터의 의미에 맞춘다.** 현재 작업 설명과 기존 계약에서 제공하는 현재 프로필만 사용한다. Dev n/100은 합성 진행 비율이므로 실제 처리 인원수로 표현하지 않는다. currentOrdinal과 totalCount가 모두 제공되는 경우에만 “현재 n번째 / 대상 N개”로 표시한다. 현재 순번을 완료 개수로 표현하지 않는다. 단위가 불명확한 track의 n/100은 기본 화면에서 숨기고 작업 상태로 전달한다. 고정 대상 표식·새 대상 DTO는 1차 범위에서 제외한다.
3. **시간 안내를 환경에 맞춘다.** Dev의 45초는 합성 실행 설정이며 실제 대기시간 보장이 아니다. “테스트 분석은 약 45초 동안 진행돼요”처럼 Dev 전용 안내로 표현한다. Production은 처리 시간이 달라질 수 있다는 안내를 사용한다. 기존 300초 목표 모델을 실측으로 해석하거나 정확한 종료 시각·카운트다운·경과 시간 기능을 추가하지 않는다.
4. **읽을 수 있는 설명과 의미를 제공한다.** 주요 설명은 본문 14~16px를 기준으로 하고 작은 시간 안내의 대비도 강화한다. 실제 격자·상태 색상을 포함한 최종 배경에서 확인한다. 주제목과 전체 진행값의 progressbar 이름·현재값·범위를 제공하고 기존 aria-live의 상태 안내를 유지하되 매 변화가 과도하게 반복 낭독되지 않게 확인한다. 이것만으로 전체 접근성 PASS를 선언하지 않는다.
5. **이탈 안내와 보관함을 연결한다.** 기존 판독 지속 안내와 테스트 환경 header를 유지한다. 진행·완료 내역 조회가 가능한 기존 보관함 경로로 CTA를 제공한다. 실패 실행의 보관함 노출·복구는 약속하지 않는다.
6. **실행 실패와 조회 오류의 행동을 구분한다.** 아래 행동 정의를 적용한다. 새로운 run 재실행·환불·완료 알림을 추가하지 않는다. 실제 카드·provider·AI·DB·결과 페이지·랜딩 마케팅 카피는 변경하지 않는다.

## 오류 화면 행동 정의

현재 세 시안은 모두 진행 중 상태다. 아래는 승인 후 구현할 행동 기준이며 실패·조회 오류의 시각 시안은 없다.

| 상태 | 사용자에게 보여줄 행동 | 보존할 경계 |
| --- | --- | --- |
| 종료된 분석 실패 | 기존 안전한 오류 안내와 “새 분석 시작하기”로 /analyze 복귀 | 현재 run 재시도처럼 표현하지 않는다. 실패 내역의 보관함 복구를 약속하지 않는다. |
| 미존재 요청·확정 HTTP404 | 요청을 찾을 수 없다는 안내와 “새 분석 시작하기”로 /analyze 복귀 | 진행 중처럼 표시하지 않는다. 다른 사용자의 요청이나 원시 오류를 노출하지 않는다. |
| 유효한 요청의 일시 조회 오류 | 일시 조회 오류를 구분하고 기존 hook refetch로 “다시 조회” | 새 분석·결제·provider 실행을 유발하지 않는다. HTTP503/네트워크 주입 검증은 아직 하지 않았다. |

## 승인 후 수용 기준

- 초기·중간·병렬 진행·마지막 작업에서 전체 값과 세 작업의 의미가 유지되고 25% 예시가 런타임 고정값이 되지 않는다. 합성 n/100을 실제 수집 인원으로 표시하지 않는다.
- 같은 실행 URL 새로고침에서 진행이 이어지고 완료 시 기존 결과 화면으로 자동 이동한다. 종료 실패와 미존재 조회의 새 분석 CTA는 /analyze로 복귀한다. 일시 오류의 다시 조회는 기존 요청만 재조회한다.
- 보관함 CTA는 진행·완료에 지원되는 기존 경로를 사용하며 실패 실행 복구 문구를 만들지 않는다. 키보드로 버튼을 사용할 수 있고 상태를 색상만으로 전달하지 않는다.
- Dev 테스트 header·합성 시간 안내와 Production의 변동 가능한 시간 안내가 분리된다. 현재 프로필 표시·기존 진행 계산·결과 UI·결제/provider/DB·랜딩 카피의 동작은 보존한다.
- 승인 후 실제 Dev 데스크톱과 크기를 확인한 모바일 화면에서 줄바꿈·가로 넘침·주요 설명·현재 활동·보관함 CTA를 다시 검수한다. 이번 생성 이미지나 이전 모바일 검수를 새 구현의 PASS 근거로 대체하지 않는다.
- 기존 [owner 표현 검사](/Users/youngminpark/.codex/worktrees/continuation-20261003/yeosachin_scanner/tests/analysis/results/owner-view-presentation.test.ts), [진행 표시 검사](/Users/youngminpark/.codex/worktrees/continuation-20261003/yeosachin_scanner/tests/analysis/results/v2-progress-display.test.ts), [요청 계약 검사](/Users/youngminpark/.codex/worktrees/continuation-20261003/yeosachin_scanner/tests/analysis/results/use-analysis-progress-request-contract.test.ts), [프로필 표시 검사](/Users/youngminpark/.codex/worktrees/continuation-20261003/yeosachin_scanner/tests/analysis/results/components/progress-faces.test.tsx) 등을 우선 재사용한다. 구현 후 변경에 필요한 타입·UI·회귀 검사와 독립 리뷰는 Root가 진행한다.

## 미결 선택과 검증 한계

사용자가 1·2·3안 중 하나 또는 수정 방향을 선택하고 위 공통 요구·오류 행동 범위를 승인해야 구현에 들어간다. 한 항목만 선택·승인한 경우 나머지가 자동 승인된 것으로 해석하지 않는다. 이전 결과 시안 1·2·3은 미채택 참고 제안이며 이번 진행 시안과 별개다. 이전 UX finding 5건과 결과 점수/수집 문구를 해결·변경하는 승인이 아니다.

실물 모바일·스크린리더·HTTP503/네트워크 중단·Production 실제 분석 시간은 미검증이다. 합성 성공은 실제 AI 품질·provider·실제 결제사의 증거가 아니며, 청구·전체 egress 감사를 주장하지 않는다. 이번 변경은 문서뿐이므로 새 앱 검사는 실행하지 않았다. 시안 미승인은 이미 완료된 Dev 인프라 구축의 미완료를 뜻하지 않는다.
