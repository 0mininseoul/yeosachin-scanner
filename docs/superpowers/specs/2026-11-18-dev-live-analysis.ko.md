# Dev 무결제 실제 분석 설계

2026-11-18 승인. Dev 기본값은 기존 합성 분석이다. 실제 분석은 운영과 같은 공급자 및 분석 코드의 실행을 확인하는 별도 선택지다. 실 결제는 Dev 계정에 바인딩된 테스트 이용권으로 대체한다. 기존 카카오 접근 제한과 합성 시나리오를 유지한다.

- Dev 웹은 승인된 Basic 실행의 대상, 만료 시각, 실행 ID를 서버에서 확인한다. 실행 ID로 생성한 고정 사전 점검 키와 이용권 nonce를 반복 요청에 사용한다. 사전 점검 이후 소유자와 저장된 모드를 확인하고 기존 사전 점검, 제외 선택, 테스트 이용권, admission, 작업 큐, 진행·결과 조회를 사용한다.
- Dev DB, 사전 점검 및 분석 큐, private Cloud Run 워커, OIDC 서비스 계정, 자격 증명, 결과 이미지 저장소를 분리한다. 배포가 이를 확인할 수 없는 경우 실제 실행 요청을 거절한다. 운영 앱 경로와 모의 분석의 기존 결과 보관함을 보존한다.
- 1차 배포에서는 외부 호출을 비활성화한다. 별도로 비용을 승인한 공개 테스트 대상 한 개에 Basic 한 회를 허용하도록 준비한다. 이전 승인 재요청은 같은 사전 점검/이용권으로 복구한다. 공급자·모델별 상한과 재시도 누적 예산을 확인한 후 사용자가 직접 실행한다.
- 승인된 실행과 결과를 구분해 표시한다. 모의 분석은 이전처럼 45초 시간 기반이며 실제 분석은 기존 분석 워커 상태를 사용한다.

수용 기준은 Dev 미등록/미승인/만료 거부, Dev 실제 모드의 운영 유입 차단, 잘못된 DB/queue/worker 설정 차단, 동일 승인 요청 재사용, 기존 합성 정상, 소유자가 실제 경로의 진행 및 결과를 재조회 가능, 외부 공급자 호출 없이 관련 코드 검사와 배포 검증이다. 앞으로 실제 공급자 호출 성공과 실측 비용은 별도의 증거로 확인한다.
