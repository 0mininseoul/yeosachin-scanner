# Dev 무결제 실제 분석 구현 계획

목표는 승인된 한 건의 실제 분석을 Dev에서 운영 경로에 넣고, 기본 모의 분석과 분리하여 조회하는 것이다. [승인한 설계](../specs/2026-11-18-dev-live-analysis.ko.md)를 실행한다.

1. `lib/services/dev-ui/live-approval.ts` 및 `live-analysis.ts`에서 초기 비활성 상태, 승인 만료, 단일 Basic 대상, 고정 키, Dev Auth와 DB 소유권을 검증한다. 기존 routes 및 proxy의 요청 분기 검사에서 운영/모의/실제 경로를 대조한다.
2. preflight 생성·조회·제외, 서명 이용권, 진행·결과의 기존 route를 재사용한다. 실제 모드 사용 시 서버에서 서명하고, production 결제 엔드포인트는 Dev에서 닫는다. 기존 route 회귀 검사를 실행한다.
3. `/analyze`에 기존 모의 분석과 실제 분석 선택지를 연결한다. Dev 실행 화면에 사전 점검, 선택, 합성 여부 및 승인 대기를 표시한다. 기존 진행·결과 화면의 Dev 실제 모드에 정상 조회를 연결한다.
4. Dev 프로젝트·워커·큐·DB 격리 계약 및 설치 순서를 기록한다. 실제 호출 없이 로컬 테스트, 읽기 기반 점검, Dev 승인 전 거부를 검증한다. 실제 자격 증명 및 실행 예산은 별도로 준비한다.
5. 독립 리뷰, 관련 검사, PR, 승인 전 Dev 배포 확인, main 병합·동기화 순으로 마감한다. 실제 공급자 호출은 이 단계의 검증 대상에서 제외한다.
