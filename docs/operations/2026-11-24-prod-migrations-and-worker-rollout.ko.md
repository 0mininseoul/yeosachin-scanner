기간: 2026-11-23 21:00 ~ 2026-11-24 02:31 KST.

## 요약

- **조사**: 운영 Supabase의 `supabase_migrations.schema_migrations`가 main과 어긋나 있었다. main에만 있는 버전이 19개, 원격 기록에만 있는 버전이 6개였다.
  - 19개 중 8월 6개는 운영에 효과가 이미 들어가 있었다.
  - 11월 13개는 별도 Dev Supabase에만 적용되고 운영에는 빠져 있었다.
- **적용**: 사용자 승인을 받아 다음을 적용했다.
  - 11월 13개(01:04 KST)
  - PR #677의 2개(01:49 KST)
- **워커 전환**: Cloud Run `analysis-preflight-worker`(01:57 KST)와 `analysis-paid-worker`(02:16 KST)를 main `cf108985`로 바꿨다. 이미지만 바꾸고 다른 설정은 그대로다.
- **당시 운영 상태**: 주문이 없었고, 공개 분석은 동결 상태였다(`ANALYSIS_CAPACITY_PUBLIC_FREEZE_ENABLED=true`). 그래서 실제 Standard 분석 경로는 이번에 실측하지 않았다.
- **하지 않은 것**: `migration repair`, 기록 행 수정, 데이터 변경, 환경 변수·시크릿·IAM·큐·스케줄러 변경. 이 PR이 저장소에서 바꾸는 것은 이 문서 하나다.

`analysis-worker`는 스케줄러 호출이 없고, 연결된 큐(`analysis-pipeline`, `analysis-v2`)가 PAUSED인 레거시 워커라 대상에서 뺐다.

### 방법

11/18 운영 preflight 배포와 같은 방식이다.

1. 배포 SHA를 정했다: Vercel 운영 SHA = main `cf108985`이고, 그 SHA의 GitHub CI가 success다.
2. 그 SHA의 `git archive` 소스로 `gcloud run deploy --source --no-traffic`를 실행했다.
   - 빌드 환경 입력은 직전 운영 빌드와 같은 공개 Supabase URL·anon 키에, `NODE_OPTIONS=--max-old-space-size=4096`를 더했다.
   - 빌드 서비스 계정은 기존 전용 계정이다.
3. 서빙 리비전과 후보 리비전을 필드 단위로 비교했다. 비교 항목은 env, 시크릿 참조, 서비스 계정, 동시성, 타임아웃, 스케일·실행 환경 주석, 라벨이다.
4. 캡처한 후보 리비전 이름으로만 100% 전환했다. 서빙 리비전이 그사이 바뀌지 않았는지 확인한 뒤에 전환했다.

- env·시크릿·IAM·큐·스케줄러는 바꾸지 않았다.
- `--build-service-account`에는 `projects/…/serviceAccounts/…` 전체 리소스 형식이 필요하다. 이메일만 넘긴 첫 시도는 인자 검증에서 멈췄고, 빌드·리비전은 생기지 않았다.

## 5. 남은 일

- **Standard 분석 시험**: 공개 분석 동결을 풀기 전에 실제 Standard 분석 경로를 소규모로 시험해야 한다. 이번 배포로 실측한 것은 스케줄러 recover·retention 경로뿐이다.
- **새 마이그레이션의 운영 적용**: main에 마이그레이션이 병합되면 운영에도 적용해야 한다.
  1. 원격 기록과 main을 비교한다.
  2. 격리 workdir을 만든다: main에서 8월 6개를 빼고, 원격 전용 6개를 placeholder로 넣는다.
  3. dry-run으로 대상이 정확한지 확인한다.
  4. 원격 최신 버전보다 오래된 버전이 있을 때만 `--include-all`이 필요하다. 이때는 따로 승인을 받는다.
- **기록 차이 유지**: 8월 로컬 전용 6개와 원격 전용 6개의 기록 차이는 10/3 결론대로 둔다.
- **미조사 1건**: `20260814000854`는 원격 기록에 이름과 statements 없이 행만 있다. 해당 함수의 운영 본문은 main 파일과 다르며, 이번 범위에서는 조사하지 않았다.

## 비공개 처리

- 토큰, DB 비밀번호, 쿠키, 사용자 UUID는 읽거나 저장하지 않았다.
- 원격 결과는 md5·길이·boolean·집계로만 받았다.
- 빌드 입력, 백업, workdir은 owner-only 임시 디렉터리에 두었다가 작업이 끝난 뒤 삭제했다.
- 실행에 쓴 스크립트에는 로컬 경로가 들어 있어 저장소에 넣지 않았다.
