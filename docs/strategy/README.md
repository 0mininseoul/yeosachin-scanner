## 한 장 요약 (2026-07-31, rev.3)

### 지금까지 만난 사람

**외부 가입 25명, 상당수가 플랜 화면 도달, 결제 0명.** 결제·결과 조회·공유는 전원 내부 테스터.

**하지만 두 가지를 동시에 기억해야 한다.**

1. **0/25는 "수요 없음"이 아니다.** 95% 신뢰구간 상한이 약 11%이고, 실제 전환율이 2%여도 25명 중 0명이 나올 확률이 약 60%다.
2. **더 중요한 건 그 25명이 누구였냐다.** 유입은 대부분 파운더가 올린 Threads·X·에브리타임 글이고, 그건 정의상 **재미·호기심 맥락**이다. SEO는 세팅 1~2일차라 기여가 없다(클릭 2·노출 4).

> **즉 우리는 재미 트래픽에 불안 해소 가격표를 붙여 시험했고 그게 0으로 나왔다. 썸·연애 중 특정 의심자는 아직 한 번도 만난 적이 없다.**

### 경쟁하는 문제 가설

| 가설 | 내용 | 함의 |
|---|---|---|
| **H-A** 발견 | 여사친 관계를 **잘 몰라서** 불안하다 | 파는 것 = *발견*. 현행 카피와 정합 |
| **H-B** 판정 (메인) | 이미 **1~5명을 특정해 의심 중**이다 | 파는 것 = *판정*. 현행 제품 설계와 정합 |
| **H-C** 단계 조절 | **썸은 H-A, 연애는 H-B** | 둘은 경쟁 가설이 아니라 같은 곡선의 두 지점 |

H-C의 근거는 소유자 지인 2명의 진술 — **여자친구일 때보다 썸일 때 팔로잉 목록을 더 다 뒤진다.** n=2라 방향 힌트일 뿐이지만, 썸에서는 *직접 묻기*라는 대안이 비용이 아니라 **아예 불가능**하다는 점이 붙는다.

### 지금 알게 된 구조적 결함 하나

**플랜 화면에 결과물 미리보기가 없다.** 유저는 랜딩(재미 훅) → 로그인 → 남친 아이디 입력 → preflight → **가격표** 순으로 이동하고, **한 번도 실물을 보지 못한 채 6,900~9,900원을 요구받는다.**

### 다음 4가지, 이 순서대로

1. **플랜 화면 이탈 지점 조회** — 30분, 코드 0줄. 이탈 위치가 원인을 지목한다(가격이냐, 신뢰냐, 결제창 마찰이냐)
2. **이탈자 인터뷰** — 25명 중 연락 가능한 사람. *"결제 화면 나오기 직전에, 뭐가 나올 거라고 생각하셨어요?"*
3. **콜드 인터뷰 6명** (썸 3 + 연애 3) — H-A/H-B/H-C를 가른다
4. **서버측 계측** — 첫 결제가 나오기 전에는 끝나 있어야 한다

**하지 않을 것**: 얼리버드 결제 배관 신규 엣지케이스, 원가 최적화(분모가 0), 상품 구조·가격 변경(아래 참조).

## 논의 중 — 승인 전까지 방향으로 기록하지 않음

**소유자 제안**: 재미는 원가상 무료로 못 하니 불안 해소를 타겟해 진지한 컨셉 + 보고서 파일 + 고가로 전환.

- **지지**: 유일하게 돈이 도는 비교군인 타로·사주·궁합이 2~5만원대다. 현재 가격은 *재미로는 비싸고 불안 해소로는 싼* 구간일 수 있다
- **반대**: **파일은 구매 후 만족을 푸는 레버인데, 관측된 실패는 구매 전이다.** 25명은 결과를 본 적이 없다. 값어치를 못 느낀 게 아니라 **보지도 않고 나갔다**
- **같은 직관의 구매 전 버전**: 결제 전 **샘플 리포트 공개**. 원가 0이고 위 1·2번 결과로 바로 검증된다

**결정 시점**: 이탈 지점 + 이탈자 인터뷰 결과가 나온 뒤.

## 철회된 것

rev.1의 **1:1 판정 wedge**(계정 2개로 그 관계만 판정하는 축소 상품)는 rev.2에서 철회됐다. 1:1은 전수조사의 진부분집합이라 새 가치를 만들지 않고, 정보 비대칭이 가장 약한 지점이며, 근거였던 페르소나 가설이 순환 논증이었다. 상세는 [재정립 문서 §4.1](./2026-07-31-lean-restatement.md).

## 근거 범위와 한계

저장소의 코드·운영 문서·git 이력 + 소유자가 확인해 준 사실. **고객 인터뷰 원본은 아직 없다** (지인 관찰 2건 제외).

주의할 함정 — **저장소는 팀이 만든 것이므로, 저장소를 읽어 얻은 "고객에 대한 결론"은 팀의 가정을 되읽은 것이지 외부 진실이 아니다.** rev.1이 실제로 이 오류를 범했고(자체 작성 후기와 팀의 설계 결정을 고객 증거로 취급), rev.2에서 정정했다.

## 갱신 규칙

- **린 캔버스가 전략 현황의 정본이다.** 다른 문서는 캔버스의 칸을 인용하되 중복 관리하지 않는다
- 가설이 채택·기각되면 **캔버스와 재정립 문서를 함께** 고친다
- **제품 방향에 관한 큰 의사결정은 소유자 승인 후에만 문서에 반영한다.** 논의 중인 안은 "논의 중" 절에만 둔다
- 가격·원가 정본은 [운영 비용 및 가격 모델](../operations-cost-model.md). 결제·주문·분석 원장은 Supabase
