## 한 장 요약 (2026-08-05)

### 실측 퍼널 — 관리자 제외

| 단계 | uniques |
|---|---:|
| `landing_viewed` | 341 |
| `target_submitted` | 108 |
| **`auth_completed`** | **27** |
| `preflight_succeeded` | 18 |
| `plan_viewed` | 18 |
| `plan_selected` | 10 |
| `checkout_started` | 5 |
| `checkout_redirected` | 3 |

**병목은 가격이 아니라 로그인이다.** 아이디를 입력한 108명 중 **81명이 로그인에서 빠진다.** 플랜부터 결제까지 전체 손실은 15명이다.

**가격을 본 사람이 18명뿐**이라 "아무도 안 산다"는 아직 성립하지 않는다. 0건의 95% 신뢰구간 상한이 약 15%다.

### 원장으로 확인한 것

- **외부 가입 28명**(`users` 29행 − 관리자 1), 그중 **결제 0명**
- **실매출 0원.** 결제 흔적이 있는 주문 10건이 전부 관리자이고, `actual_amount_krw`도 대부분 `0`이다
- **`analysis_count > 0`인 유저는 관리자 1명뿐** — 외부 유저 중 결과를 받아본 사람이 아직 없다
- 계측 불일치 2건: `payment_confirmed_viewed`가 관리자 1명을 3명으로 갈라 세고, `preflight_started`는 Amplitude 26명 vs 원장 5명

### 경쟁하는 문제 가설

| 가설 | 내용 |
|---|---|
| **H-A** 발견 | 여사친 관계를 **잘 몰라서** 불안하다 |
| **H-B** 판정 (메인) | 이미 **1~5명을 특정해 의심 중**이다 |
| **H-C** 단계 조절 | **썸은 H-A, 연애는 H-B** — 관계 단계가 조절 변수 |

H-C의 근거는 소유자 지인 2명의 진술(여자친구일 때보다 썸일 때 팔로잉을 더 뒤진다). 썸에서는 *직접 묻기*가 비용이 아니라 **아예 불가능**하다는 점이 붙는다.

### 구조적 제약 하나

**DM을 볼 수 없다.** 소유자가 서비스를 설명할 때마다 첫 질문이 "뭘 보고 판단하냐" → "DM 보냐"였고, 좋아요·댓글이라고 답하면 실망이 돌아왔다. 사람들의 증거 기준이 DM이라면 **"진지한 유료 판정 도구" 포지션은 구조적으로 그 기준을 충족할 수 없다.**

## 승인된 방향

**로그인을 결제 클릭 시점으로 옮긴다.** preflight 결과·샘플 리포트·플랜/가격까지 로그아웃 상태로 공개하고, [결제하기]에서만 로그인을 요구한다. 샘플은 같이 낸다 — 두 레버가 서로 다른 퍼널 구간에 나타나므로 순차 출시 없이도 귀속된다. 익명 preflight의 프로필 수집은 Apify로 격리해 버너 계정 리스크를 매출과 연동시킨다.

## 논의 중 (미승인)

진지한 컨셉 + 보고서 파일 + 고가 전환. **파일은 구매 후 만족을 푸는 레버인데 관측된 실패는 구매 전**이다 — 외부 유저 중 결과를 본 사람이 0명이라 "값어치를 못 느꼈다"는 판단 자체가 불가능하다.

## 다음 우선순위

1. **Basic/Standard 건당 원가 실측** — 가격이 990/1,990원인 지금 원가는 마진이 아니라 **가능한 포지셔닝 범위**를 결정한다
2. **로그인 이전 배포** — 가격을 보는 사람을 18명에서 세 자리로
3. **인터뷰 6명** (썸 3 + 연애 3) — H-A/H-B/H-C 판별
4. **계측 수정** — 백엔드 인계 프롬프트

## 근거 범위

저장소 코드·운영 문서·git 이력 + Amplitude 실측 + Supabase 원장 + 소유자 확인. **고객 인터뷰 원본은 아직 없다**(지인 관찰 2건 제외).

주의할 함정 — **저장소는 팀이 만든 것이므로, 저장소를 읽어 얻은 "고객에 대한 결론"은 팀의 가정을 되읽은 것이지 외부 진실이 아니다.** 최초 판본이 실제로 이 오류를 범했고(자체 작성 후기와 설계 결정을 고객 증거로 취급), 이후 정정했다.

## 갱신 규칙

- **린 캔버스가 현재 상태의 정본이다.** 다른 문서는 인용만 하고 중복 관리하지 않는다
- **제품 방향에 관한 큰 의사결정은 소유자 승인 후에만 반영한다.** 논의 중인 안은 "논의 중"에만 둔다
- 가격·원가 정본은 [운영 비용 및 가격 모델](../operations-cost-model.md). 결제·주문·분석 원장은 Supabase
