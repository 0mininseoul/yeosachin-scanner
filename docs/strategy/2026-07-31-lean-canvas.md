## ① 문제

### 경쟁하는 두 가설 — 이 캔버스의 핵심 쟁점

> **H-A (발견 가설, 기존)** ⚪
> 연애 중인 20대 여성은 남자친구와 그의 '여사친'들 사이의 관계를 **잘 모르기 때문에** (특히 매력적인 남성일수록) 지속적으로 불안을 느낀다.

> **H-B (판정 가설, 메인 승격)** ⚪
> 잘 모르는 게 아니다. **이미 유심히 보고 의심하는 계정이 1~5명 있다.** 썸 때부터 팔로잉 목록을 봐 왔고 연애 중 알게 된 정보가 쌓이므로 아예 모를 수 없다.

**두 가설은 정반대의 제품·카피 결정을 낳는다.**

| | H-A가 맞으면 | H-B가 맞으면 |
|---|---|---|
| 파는 것 | **발견** — "당신이 모르는 사람이 있습니다" | **판정** — "당신이 걸리는 그 사람, 맞습니다/아닙니다" |
| 핵심 산출물 | 전체 목록과 성별 분류 | 이미 아는 후보들의 **상대 순위와 근거** |
| 현재 랜딩 카피 | 정합 (전수조사 소구) | 부분 정합 |
| 현재 제품 설계 | 부분 정합 | 정합 (상위 1~3명 딥 분석) |

> **H-C (단계 조절 가설)** 🟡
> 관계 단계가 조절 변수다. **썸 단계는 축적된 정보가 적어 H-A(발견)에 가깝고, 연애가 길어질수록 H-B(판정)로 이동한다.**
> 근거: 소유자 지인 2명이 "여자친구일 때보다 썸일 때 팔로잉 목록을 더 다 뒤져본다"고 진술. n=2이므로 방향 힌트일 뿐이다.

**H-C가 맞으면 A와 B는 경쟁 가설이 아니라 같은 곡선의 두 지점**이고, 세그먼트를 단계로 나눠야 한다.

### 파생 문제

- **혼자서는 해소하지 못한다** ✅ — 친구 단톡방에 캡처를 보내고 무료 "구분법" 콘텐츠를 소비하는 행동이 널리 관찰된다
- **직접 물으면 관계 비용이 든다** ⚪ — 그리고 **썸 단계에서는 비용이 아니라 아예 불가능하다.** 사귀지도 않는 사이에 "이 여자들 누구야"를 물을 수 없다. 사실이라면 썸 세그먼트에는 **대체재 자체가 없다**

### 기존 대안 (진짜 경쟁자)

| 대안 | 비용 | 속도 | 비고 |
|---|---|---|---|
| 직접 팔로잉 스크롤 | 0원 | 즉시 | **가장 강력한 경쟁자** |
| 단톡방에 캡처 공유 | 0원 | 수 분 | 사회적 지지까지 획득 |
| 부계정 훔쳐보기 | 0원 | 즉시 | 흔적 위험 |
| 무료 "구분법" 콘텐츠 | 0원 | 즉시 | 재미 축을 이미 점유 |
| 직접 묻기 | 관계 비용 | 즉시 | **썸에서는 불가** |
| **타로·사주·궁합·연애상담** | **2~5만원대** | 수십 분 | ⚪ 유일하게 **돈이 실제로 도는** 비교군. 가격 앵커 근거가 될 수 있다 |

## ② 고객 세그먼트

| 세그먼트 | 특징 | 지불 의사 | 상태 |
|---|---|---|---|
| **S1. 썸 단계 여성** | 검증 욕구 최고. 직접 묻기 **불가능**. 정보 축적 적음 → H-A 쪽 | 미검증 | 🟡 n=2 관찰 |
| **S2. 연애 중 여성** | 기존 타겟. 정보 축적 있음 → H-B 쪽. 직접 묻기는 가능하나 비용 발생 | 미검증 | ⚪ |
| **S3. 재미·호기심** | 커뮤니티·소셜에서 유입. 특정 의심 없음 | 낮을 것으로 추정 | ⚪ |

### 지금까지 만난 사람 (원장 기준) ✅

Supabase `users` 29행 = **관리자 1명**(2026-01-23) + **외부 28명**(2026-07-24~08-03).

| 항목 | 값 |
|---|---:|
| 외부 가입 | **28명** |
| 그중 플랜·가격 화면 도달 | **18명** |
| 그중 결제 | **0명** |
| `analysis_count > 0`인 유저 | **1명 (관리자뿐)** |

**즉 외부 유저 중 분석 결과를 받아본 사람이 아직 아무도 없다.**

### 0건을 과대 해석하지 말 것

가격을 본 사람이 **18명**이므로, 결제 0건의 95% 신뢰구간 상한은 약 **15%**다. 실제 전환율이 2%여도 18명 중 0명이 나올 확률이 약 70%다. **"아무도 안 산다"가 아니라 "아직 아무것도 모른다"가 맞는 서술이다.**

### 유입 세그먼트에 대한 주의

이전 판본은 "지금까지 만난 사람은 대부분 S3(재미)"라고 단정했다. **⑤에서 확인했듯 유입 문구는 "의심되면"을 명시적으로 겨냥하고 있어 그 단정은 과했다.** 현재 정확히 말할 수 있는 것은 **유입 맥락(홍보게시판, "내가 만들었어 해볼래?")이 재미·무료 쪽으로 기울어 있다**는 것까지다.

### Early Adopter — 아직 선언하지 않는다

근거 없이 좁히면 잘못된 세그먼트에 최적화한다. 인터뷰 6건(썸 3 + 연애 3)과 첫 외부 코호트 이후에 선언한다.

## ③ 고유 가치 제안 (UVP)

**미확정. 두 후보가 각각 다른 세그먼트·문제 가설에 대응한다.**

> **후보 1 (관계 비용 축)** ⚪
> "싸우지 않고, 흔적도 남기지 않고, 확인합니다."
> → 직접 묻기의 대체. S2(연애)에 대응. **썸(S1)에서는 '대체'가 아니라 '유일한 수단'이 되므로 더 강해진다**

> **후보 2 (규모 축)** ⚪
> "혼자서는 절대 못 세는 순위를, 대신 세어 드립니다."
> → 무료 대안이 물리적으로 못 하는 것. H-B(판정)와 현재 제품 설계에 정합. 현행 랜딩 카피가 이쪽에 가깝다

**하이 컨셉**: 연애판 거짓말 탐지기 — 사람이 아니라 계정에 대고 쓰는.

### 🚨 구조적 신뢰도 상한 — DM 문제 🟡

**이 캔버스에서 가장 질 좋은 외부 신호다.** 소유자가 주변에 이 서비스를 설명할 때마다 반복 관찰된 것:

1. 첫 질문이 일관되게 **"뭘 보고 판단하냐"**
2. 이어서 **"DM을 보느냐"**
3. 좋아요·댓글을 본다고 답하면 **눈에 띄게 실망**

반복적이고, 일관되고, **우리가 유도하지 않은 자발적 반응**이다.

**함의**: 사람들의 멘탈 모델에서 '바람의 증거'는 DM인데 우리는 그걸 볼 수 없다. 좋아요 방향과 댓글 친밀도를 아무리 정교하게 교차해도 *"그건 진짜 증거가 아니잖아"*를 넘지 못한다. **즉 "진지한 유료 판정 도구" 포지션은 고객이 요구하는 증거 기준을 구조적으로 충족할 수 없다.**

*"결과를 실제로 보면 다르다"*는 반론은 약하다. **구매 결정은 결과를 보기 전에 일어나기 때문이다.**

검증: [인터뷰 가이드 §4-B](./2026-07-31-interview-guide.md) — 제품을 언급하지 않고 과거 행동으로 상대의 증거 위계를 확인한다.

### 명시적으로 약속하지 않는 것

현재 면책은 "재미 목적으로만" 한 줄인데 카피는 확신을 판다("근거까지", "한 명도 빠짐없이"). **첫 외부 고객이 생기는 순간 환불·분쟁의 1순위 원인이 된다.**

- 바람 여부를 판정하지 않는다. **관계의 밀도**를 판정한다
- 공개된 상호작용만 본다. DM·스토리·통화·오프라인은 보지 않는다
- 트래킹 신호는 좋아요 방향, 댓글 친밀도, 맞팔·최근 맞팔 순위, 프로필/피드 스타일뿐. **좋아요 시각과 스토리 반응은 트래킹하지 않으므로 카피에서 암시하지 않는다**

## ④ 솔루션

**현행 (구현 완료)**: 맞팔 전수 수집 → 성별 선별 → 상호작용 교차(좋아요 방향·댓글 친밀도) → 위험 순위 → 상위 1~3명 딥 분석 2문장 총평

**진짜 정보 우위** ⚪: 계정 하나를 보는 건 유저가 우리보다 빠르다. **수백 명을 교차해 상대 순위를 매기는 것은 인간이 물리적으로 불가능하다.** 우위는 규모에 있다.

### 🚨 결함 1 — 로그인 벽 (가장 큰 손실)

현재 경로: **랜딩에서 남친 인스타 아이디 입력 → 즉시 로그인 요구 → preflight → 플랜·가격**

`components/landing-page.tsx`의 `handleStart`가 아이디를 받자마자 비로그인 사용자에게 로그인 모달을 띄운다. **남자친구의 아이디를 입력한 직후에 카카오·구글로 신원을 밝히라고 요구한다.** 아직 아무 가치도 주지 않은 시점이고, 유저 입장에서는 떳떳하지 못한 행위 직후에 신원을 요구받는 구조다.

⑧이 보여주듯 여기서 **81명**이 빠진다. 플랜~결제 전체 손실(15명)의 5배가 넘는다.

### 결함 2 — 플랜 화면에 결과물 미리보기가 없다

`app/analyze/page.tsx`는 요금제, 선착순 문구, 소요시간("약 5~10분")만 보여준다. **한 번도 실물을 보지 못한 채 결제를 요구받는다.**

### ✅ 승인된 방향 — 로그인을 결제 클릭 시점으로 (2026-08-05)

소유자 승인. 상세 설계는 [익명 preflight UX 설계](./2026-08-05-anonymous-preflight-ux-design.md).

- preflight 결과·**샘플 리포트**·플랜/가격까지 **로그아웃 상태로 공개**하고, [결제하기]에서만 로그인을 요구한다
- 목적은 이탈 감소보다 **가격을 보는 사람 수를 18명에서 세 자리로 만드는 것**이다. 그래야 가격 가설이 처음 시험대에 오른다
- **샘플과 로그인 위치를 동시에 바꾼다.** 두 레버는 서로 다른 퍼널 구간(`target_submitted→plan_viewed` / `plan_viewed→plan_selected`)에 나타나므로 순차 출시 없이도 귀속된다
- 익명 preflight의 대상 프로필 수집은 **Apify로 격리**한다. 버너 계정을 결제자 분석에만 써서 계정 정지 리스크를 매출과 연동시킨다

### 논의 중 (미승인)

진지한 컨셉 + **보고서 파일** 형태 + 고가 전환. 파일은 **구매 후 만족**을 푸는 레버인데 관측된 실패는 **구매 전**이다 — 외부 유저 중 결과를 받아본 사람이 0명이라 "값어치를 못 느꼈다"는 판단 자체가 아직 불가능하다. 승인 전까지 방향으로 기록하지 않는다.

### 유입 문구가 무료 기대를 만들었을 가능성 🟡

에브리타임 홍보게시판 글(2026-07-29, 가천대)의 실제 문구:

> "남친 바람 의심되면 꼭 해봐야 하는 거 1가지 / 연애하는 남자면 생각보다 위장여사친 많음 / **의심되면** 위장여사친들 **전수조사**해봐야 해 / **그래서 내가 만들었어 해볼래?** / 남친 인스타만 치면 위장여사친 찾아줌 / **피드백 언제나 환영 !!**"

두 가지를 동시에 말해준다.

1. **카피는 "의심되면"(H-B)과 "전수조사"(H-A)를 함께 쓴다.** 재미 소구가 아니다. "재미 트래픽"이라는 이전 판본의 단정은 과했다
2. **그런데 "내가 만들었어 해볼래?", "피드백 언제나 환영"은 무료 베타 초대의 언어다.** 이 기대를 안고 도착한 사람이 **로그인 벽**과 **결제창**을 만난다. ⑧의 `target_submitted`→`auth_completed` 25% 통과율과 맞물리는 가설이다

게시 위치가 **홍보게시판**이라 열람 맥락이 "광고를 훑는 중"이고, 가천대 학생 집단이라 가격 민감도가 높다.

> **따라서 "결제 0건"은 S1·S2의 지불 의사를 반증하지 않는다.** 무료 기대를 안고 온 사람에게 로그인과 결제를 요구했고, 애초에 가격까지 도달한 사람이 18명뿐이다.

**그리고 이 채널은 확장되지 않는다** — 파운더 개인 계정의 도달에는 상한이 있다.

### 🚨 정정 (2026-08-06) — `Apify $0`은 달성 상태가 아니라 설계 의도다

이전 판본은 이 칸을 **✅ 검증됨**으로 표기했다. **틀렸다.** [selfhosted_auth 전략 재검토](./2026-08-06-selfhosted-auth-strategy-review.md)가 확인한 것:

- **완전한 분석 결과까지 도달한 `selfhosted_auth` E2E 성공 기록이 아직 0건이다**
- 2026-08-05에 팔로워·팔로잉·liker·comment 수집이 여러 번 성공했지만, **14개 요청 전부 최종 `failed`**

- 같은 계정에서도 성공한 날과 거절된 날이 갈린다

**즉 Apify를 껐다는 사실은 확인됐지만, 그 자리를 selfhosted_auth가 메운다는 것은 아직 확인되지 않았다.**

| 항목 | 현재 상태 |
|---|---|
| **Apify Actor** | 유료 경로에서 호출하지 않음. 다만 **그 대체가 완주한 적 없음** ⚠️ |
| **Vertex AI Gemini** | Basic/Standard **미측정**. Plus 단일 표본 `$0.5858645`가 유일한 관측치 |
| Cloud Run (인증 worker) / Cloud Tasks / 네트워크 | **미측정** |
| 버너 계정 운영비·복구 인건비 | **미측정** |
| 실패 재시도 | 실패해도 원가는 전액 발생 |

**Groble 수수료 8.69% 차감 후 순수입** (현행 가격 기준)

| 플랜 | 결제액 | 순수입 |
|---|---:|---:|

### 🚨 이 캔버스에서 가장 큰 미해결 리스크 — 가격·원가 시차

**수익은 이미 5배 낮췄는데, 그걸 정당화한 원가 절감은 아직 일어나지 않았다.**

| 시점 | 사건 |
|---|---|
| 2026-08-03 | 가격 v3 인하 (6,900→990 / 9,900→1,990) |
| 2026-08-04 | `selfhosted_auth` 전환 — 인하의 전제 |
| 2026-08-06 | **selfhosted_auth E2E 성공 0건 확인** |

지금 갈림길에 좋은 가지가 없다.

| 선택 | 결과 |
|---|---|
| Apify로 되돌린다 | 1,990원에 provider $2~4 → **건당 확정 역마진** |
| selfhosted를 고수한다 | 분석이 완주하지 못한다 → **결제받고 결과를 못 준다** |

**외부 결제가 0건이라 이 갈림길이 아직 터지지 않았을 뿐이다.** 첫 외부 결제가 들어오는 순간 둘 중 하나가 실현된다. 대응은 [전략 세션 답변](./2026-08-06-selfhosted-auth-strategy-answer.md) 참조.

### 원가 실측이 최우선인 이유

이전 판본은 "외부 유저 0명이니 원가 최적화는 분모가 0인 최적화"라고 썼다. **그건 원가가 *마진* 문제일 때 맞는 말이다.**

가격이 990~1,990원으로 내려간 지금 원가는 마진 문제가 아니라 **어떤 포지셔닝이 가능한지를 결정하는 제약**이다. 저가 바이럴로 가겠다는 결정은 **원가를 자릿수로 낮추겠다는 결정과 분리할 수 없다.**

### ⚠️ 형태가 바뀐 공급 리스크

인증 수집은 Instagram 로그인 세션을 쓴다. 공급 리스크가 사라진 게 아니라 **rate-limit에서 계정 정지로 형태가 바뀌었고, 정지되면 유료 경로 전체가 동시에 멈춘다.** ④의 승인된 방향에서 익명 preflight를 Apify로 격리하는 이유가 이것이다.

**3. 로그인을 통과해도 절반이 에러를 본다.**

**4. 공유 루프는 3단계 중 가운데만 성립한다.**

### 계측 신뢰도 — 두 건의 원장 불일치 ❌

- **`payment_confirmed_viewed` 3명은 계측 버그로 확정.** 원장의 결제 흔적 10건이 전부 관리자인데 Amplitude는 비관리자 3명을 잡는다. **관리자 한 명이 최소 3명으로 갈라진다.** 원인 미확정, 백엔드 인계 A1
- **preflight 원장도 어긋난다.** Amplitude `preflight_started` 26명 vs Supabase `analysis_preflights` 고유 `user_id` **5명**. `VALIDATION_ERROR`가 행 생성 전에 거부되는지 purge로 지워지는지 미확인. 전자라면 실패 사유를 사후 분석할 서버 원장이 아예 없다

플랜 화면 지표는 표본이 18명이라 당분간 유의미해지지 않는다. **로그인 통과율(`target_submitted` → `auth_completed`)이 당분간 유일하게 크게 움직일 수 있는 숫자이며, ④의 승인된 방향이 정확히 이걸 겨냥한다.**
