# 고객 인터뷰 가이드

- 버전: **v5 (2026-08-05)** — C1(증거 기준)을 비유도·유도 2단계로 재설계. 썸/연애 두 스크립트 분리는 v4
- 검증 대상: [린 캔버스](./2026-07-31-lean-canvas.md) ①문제 ②세그먼트 ③UVP ⑥가격
- 상위 문서: [검증 보드](./2026-07-31-validation-board.md)

## 문서 구조

```
1. 공통 준비        규칙 · 표본 · 스크리너 · 지인 처리
2. 스크립트 A       썸 단계 (3명)      ─┐
3. 스크립트 B       연애 단계 (3명)    ─┤
4. 공통 마무리 C    증거 기준 · 지불 의사 · 닫기   ← A·B 둘 다 여기로 이어진다
5. 기록 시트 · 판정 기준
6. 부록             이탈자 익명 설문 (연기)
```

**A와 B는 서로 다른 사람에게 쓰는 별개 스크립트다.** 한 명을 인터뷰할 때는 A 또는 B 하나만 따라가고, 끝나면 공통 마무리 C로 이어간다. C를 A·B에 복제하지 않은 이유는 그 구간이 단계와 무관하게 동일하고, 복제하면 두 벌이 갈라지기 때문이다.

## 이 가이드의 범위

**지금 실행 가능한 것은 콜드 문제 인터뷰 하나다.** 이탈자 조사는 개인 연락을 **철회**했고(사용 행위 자체가 떳떳하지 못한 서비스라 감시 신호가 된다), 대체안인 익명 인앱 설문도 **연기**했다(로그인 화면은 이미 지우기로 결정한 화면이다). 설계는 부록에 보존했다.

## 이 인터뷰가 답해야 하는 것

| 가설 | 어디서 갈리나 |
|---|---|
| **H-A** 발견 — 여사친 관계를 잘 몰라서 불안하다 | A2 / B2 |
| **H-B** 판정 — 이미 1~5명을 특정해 의심 중이다 | A2 / B2 |
| **H-C** 단계 조절 — 썸은 발견, 연애는 판정 | **A2와 B2의 집단 비교** |
| **대안 가용성** — 썸에서는 직접 묻기가 불가능하다 | A5 / B4 |
| **증거 기준** — 사람들이 '진짜'로 치는 증거가 DM인가 | C1 |
| **지불 의사** — 이 불안에 돈을 쓴 적이 있나 | C2 |
| **산출물 형태** — 손에 쥐는 결과물이 중요한가 | C2 |
| **제품 작동 가능성** — 썸 단계에 맞팔이 돼 있나 | **A1** |

# 1. 공통 준비

## 절대 규칙

이 여섯 개를 어기면 인터뷰 데이터가 죽는다. 죽은 데이터는 없는 것보다 나쁘다 — **틀린 확신을 준다.**

1. **제품을 설명하지 않는다. 보여주지도 않는다.** 보여주는 순간 상대는 예의상 반응하기 시작한다. "우리가 이런 걸 만들고 있는데"는 금지어다.
2. **미래를 묻지 않는다.** "이런 게 있으면 쓸래?", "얼마면 살래?"에 대한 답은 전부 거짓말이다. 악의가 아니라 사람이 자기 미래 행동을 예측하지 못하기 때문이다. **과거에 실제로 한 일만 묻는다.**
3. **우리 어휘를 먼저 꺼내지 않는다.** "의심", "위험", "여사친", "판독" — 우리가 먼저 말하면 상대가 그 프레임으로 답한다. 상대가 먼저 그 말을 쓰는지가 데이터다.
4. **의견을 묻지 않는다.** "어떻게 생각해?"가 아니라 "그때 뭐 했어?"
5. **말을 줄인다.** 목표는 상대가 70% 이상 말하는 것. 침묵이 어색해도 기다린다. 가장 중요한 문장은 대개 침묵 다음에 나온다.
6. **대명사를 쓰지 않는다.** (아래)

### 규칙 6 — 대명사를 쓰지 않는다

이 인터뷰에는 **사람이 둘, 대상이 둘** 나온다.

| 헷갈리는 것 | 왜 문제인가 |
|---|---|
| **상대방**(썸남·남친) vs **여자 계정** | "그 사람"이라고 하면 답이 섞인다 |
| **팔로잉 목록 전체** vs **특정 여자 계정** | "그거", "그 사람들"이 양쪽으로 읽힌다 |

**규칙**: 질문할 때마다 지시 대상을 말로 붙이고, **상대가 앞에서 실제로 쓴 호칭을 그대로 되받아 쓴다.**

- ❌ "그 사람들 어떻게 알게 됐어?" → ✅ "아까 떠오른다고 한 그 언니, 어떻게 알게 됐어?"
- ❌ "그 사람한테 물어봤어?" → ✅ "남자친구한테 직접 물어봤어?"

대명사 하나가 답 하나를 통째로 못 쓰게 만든다. 기록 시트를 채울 때 "이게 누구 얘기였지?"가 떠오르면 이미 늦었다.

### 금지 질문 / 대체 질문

| ❌ 금지 | ✅ 대체 |
|---|---|
| "이런 서비스 있으면 쓸 것 같아?" | "그때 그거 알아보려고 뭐 해봤어?" |
| "얼마면 살 것 같아?" | "연애 관련해서 돈 써본 적 있어? 얼마 냈어?" |
| "남친 여사친 때문에 불안했어?" | "그 사람 인스타 볼 때 주로 뭐 봐?" |
| "이 기능 어때?" | (제품 언급 자체 금지) |
| "의심되는 계정 있었어?" | "이름이나 얼굴 떠오르는 사람 있어?" |

## 표본

**6명 = 썸 단계 3명(스크립트 A) + 연애 중 3명(스크립트 B).**

5명이 아니라 6명인 이유는 **단계 비교가 이번 라운드의 핵심 질문**이기 때문이다. 통계적 유의성이 목적이 아니라 **두 집단이 눈에 띄게 다른 이야기를 하는지**를 본다. 다르면 H-C 채택, 같으면 단계는 조절 변수가 아니다.

### 스크리너 (섭외 시)

제품을 언급하지 않고 이렇게 묻는다.

> "연애나 썸 관련해서 요즘 어떤지 30분만 얘기 들어보고 싶은데 괜찮아? 서비스 홍보 아니고 그냥 리서치야."

| 배정 | 조건 |
|---|---|
| **스크립트 A (썸)** | 현재 썸 중이거나 최근 3개월 내 썸 경험 |
| **스크립트 B (연애)** | 현재 연애 중 (**기간을 반드시 기록** — H-C의 세부 곡선) |

둘 다 해당하면 **현재 상태**로 배정한다.

## 서비스를 아는 지인을 인터뷰해도 되는가

**된다. 다만 조건이 붙는다.** 아는 것 자체가 실격 사유는 아니고, 문제는 **편향의 종류**다.

| 질문 유형 | 지인 편향 | 예시 |
|---|---|---|
| **과거 행동** | **낮음** — 제품을 알아도 답이 크게 안 바뀐다 | "팔로잉 목록 마지막으로 본 게 언제야", "타로에 얼마 냈어" |
| 의견·평가 | 높음 | "이런 거 어때?" |
| 미래 의향 | **치명적** — 도와주고 싶어서 과장한다 | "이런 거 있으면 쓸 것 같아?" |

**이 가이드는 이미 과거 행동만 묻도록 설계돼 있다.** 뒤집어 말하면 **지인을 배제하는 것보다 미래 의향 질문을 배제하는 것이 훨씬 중요하다.**

1. **모르는 사람을 우선한다.** C3의 친구 소개 질문이 모르는 사람으로 가는 통로다
2. 아는 사람이면 **기록 시트에 표시하고** 판정 시 가중치를 낮춘다
3. 시작할 때 **선을 긋는다** — *"오늘은 내가 만든 거 얘기 안 할 거야. 네 경험만 들을게. 궁금한 거 있으면 끝나고 얘기해줄게."*
4. 인터뷰 중 **제품을 보여주지 않는다.** 이미 본 적 있으면 그 사실도 기록한다
5. **절대 안 되는 조합**: 이미 제품을 써 본 지인에게 C2(지불 의사)를 묻는 것. 무료로 써 봤으면 가격 감각이 오염돼 있다. 이 사람은 C1까지만 쓰고 C2는 버린다

# 2. 스크립트 A — 썸 단계 (3명)

> **이 집단에서 가장 먼저 확인할 것은 맞팔 여부다.** 썸 단계에서 맞팔 비율이 낮으면 썸 세그먼트는 시장 크기와 무관하게 **기술적으로 도달 불가능**하다. 그러면 나머지 답이 아무리 좋아도 소용없다.

## A1. 워밍업 — 단계와 작동 가능성

- "요즘 썸 타는 사람 있어? 어떻게 알게 됐어?"
- "얼마나 됐어?"
- "그 사람 인스타 해?"
- **"서로 팔로우하고 있어?"** ← ***이 라운드에서 가장 중요한 단일 질문.*** 맞팔이 아니면 그 사실을 크게 기록한다

## A2. 지식 상태 — H-A vs H-B 판별

**순서를 지킨다. 아래로 갈수록 좁아지고, 앞 질문에서 상대가 먼저 꺼낸 것이 훨씬 강한 데이터다.**

- "그 사람 인스타 얼마나 자주 봐?"
- "볼 때 주로 뭐 봐?" *(→ 여기서 팔로잉·좋아요 얘기가 나오면 상대가 먼저 꺼낸 것)*
- **"그 사람 팔로잉 목록 본 적 있어? 마지막이 언제야?"**
- **"거기 여자 계정 몇 명쯤 있을 것 같아?"**
- **"그중에 이름이나 얼굴 떠오르는 사람 있어? 몇 명쯤?"** ← *결정적 판별*

### 판정 규칙 (A·B 공통)

| 응답 | 해석 |
|---|---|
| "몰라, 엄청 많아" / 떠오르는 사람 0명 | **H-A (발견)** |
| 대략 규모를 알고, 떠오르는 사람 **1~5명** | **H-B (판정)** |
| 6명 이상 특정 | H-B이되 후보군이 넓음 — 순위의 가치가 커진다 |
| 우리가 묻기 전에 특정 인물을 **먼저** 언급 | **H-B의 가장 강한 증거** |

## A3. 언제부터 보기 시작했나

> 썸 집단에게 *"썸 때부터 봤어, 사귀고 나서 봤어?"*는 **묻지 않는다.** 지금이 썸이라 성립하지 않는다. 대신 **관심의 시작점**을 잡는다.

- **"그 사람 팔로잉 목록을 처음 본 게 언제야? 연락 시작하고 얼마나 지나서?"**
- **"썸 타기 전에도 그 사람 인스타 봤어?"** *(→ 관심 시작이 관계보다 앞서는지)*

**A2에서 1명 이상 떠올린 경우에만 이어서:**

- **"아까 떠오른다고 한 그 계정, 어떻게 알게 됐어?"** *(→ 본인이 말해줬나, 태그·댓글에서 봤나, 오프라인에서 봤나)*
- **"그 계정이 신경 쓰이기 시작한 건 언제야?"** *(→ 인지 시점과 의심 시점은 다를 수 있다)*

**A2에서 0명인 경우:**

- **"여자 계정이 있는 건 알지만 누군지는 딱히 모르는 상태인 거지?"** *(→ 확인만. 유도 금지)*

## A4. 썸 특유 — 경쟁자 프레임

> 썸에서 궁금한 것은 "여사친이 있나"가 아니라 **"나 말고 다른 사람도 있나"**일 가능성이 높다. 우리 어휘를 쓰지 않고 확인한다.

- **"이 사람이 나 말고 다른 사람한테도 이러나 싶었던 적 있어?"**
- 있다면: "그때 어떻게 했어?"
- **"그 사람 인기 많은 편이야?"** ← *기존 가설의 "매력적인 남성일수록" 조절 변수*

## A5. 대안 가용성 — 썸에서 결정적인 구간

> **가설**: 연애에서는 직접 묻기가 *비용*이지만, 썸에서는 *아예 불가능*하다. 사귀지도 않는 사이에 팔로잉을 캐물을 수 없다. 사실이면 썸 세그먼트에는 대체재가 없다.

- **"그 얘기 누구한테 했어?"** *(→ 단톡방 대안의 실재)*
- **"썸남한테 직접 물어본 적 있어?"** ← *여자 계정이 아니라 **상대방**에게 물었는지다*
  - 있다면: "물어보니까 어떻게 됐어?"
  - **없다면: "왜 안 물어봤어?"** ← ***이 구간에서 가장 중요.*** *"사귀는 것도 아닌데 어떻게 물어봐"*류의 답이 나오면 대안 부재 가설이 지지된다
- "안 물어보고 넘어간 다음엔 어떻게 했어?"

**→ 이제 공통 마무리 C로 이어간다.**

# 3. 스크립트 B — 연애 단계 (3명)

> **이 집단의 강점은 회고가 가능하다는 것이다.** 썸 때와 지금을 직접 비교시킬 수 있고, 그게 H-C를 가장 직접적으로 검증한다.

## B1. 워밍업

- "요즘 만나는 사람 있어? 어떻게 만났어?"
- **"얼마나 됐어?"** ← *기간을 반드시 기록. H-C의 세부 곡선*
- "남자친구 인스타 해? 서로 팔로우하고 있어?"

## B2. 지식 상태 — H-A vs H-B 판별

- "남자친구 인스타 얼마나 자주 봐?"
- "볼 때 주로 뭐 봐?"
- **"남자친구 팔로잉 목록 본 적 있어? 마지막이 언제야?"**
- **"거기 여자 계정 몇 명쯤 있을 것 같아?"**
- **"그중에 이름이나 얼굴 떠오르는 사람 있어? 몇 명쯤?"** ← *결정적 판별*

판정 규칙은 A2와 동일하다.

## B3. 축적 메커니즘 — H-C 직접 검증

> H-B는 *"썸 때부터 봐 왔고 연애 중 정보가 쌓인다"*고 주장한다. **연애 집단에서만 이걸 회고로 확인할 수 있다.**
>
> 아래 두 질문은 **서로 다른 것을 묻는다.** 하나로 뭉치면 답이 섞이므로 따로 묻는다.

- **"남자친구 팔로잉 목록을 처음 본 게 썸 탈 때야, 사귀고 나서야?"** ← *행동의 시작 시점*
- **"썸 때랑 지금이랑 보는 게 달라?"** ← *연애 집단에게만 가능한 회고*

**B2에서 1명 이상 떠올린 경우에만 이어서:**

- **"아까 떠오른다고 한 그 계정, 어떻게 알게 됐어?"**
- **"그 계정을 처음 알게 된 게 썸 탈 때야, 사귀고 나서야?"** ← *지식 축적 시점. **"봤어"가 아니라 "알게 된 게"**로 물어야 잡힌다*
- **"그 계정이 신경 쓰이기 시작한 건 언제야?"** *(→ 인지 시점 ≠ 의심 시점)*

**B2에서 0명인 경우:**

- **"여자 계정이 있는 건 알지만 누군지는 딱히 모르는 상태인 거지?"**
- **"혹시 예전에 신경 쓰였던 계정이 있었던 적은 있어?"** *(→ 과거형. 지금 없어도 과거에 있었으면 H-C 곡선에 쓰인다)*

**공통**

- **"남자친구 인기 많은 편이야?"** ← *"매력적인 남성일수록" 조절 변수*

## B4. 대안 가용성

> 연애에서는 직접 묻기가 **가능하다.** 그래서 물어본 적이 있는지, 물어봤을 때 무슨 일이 있었는지가 **관계 비용의 실측치**가 된다.

- **"그 얘기 누구한테 했어?"** *(→ 단톡방 대안의 실재)*
- **"남자친구한테 직접 물어본 적 있어?"**
  - **있다면: "물어보니까 어떻게 됐어?"** ← *관계 비용이 실제로 얼마인지가 여기서 나온다*
  - 없다면: **"왜 안 물어봤어?"**
- "안 물어보고 넘어간 다음엔 어떻게 했어?"

**→ 이제 공통 마무리 C로 이어간다.**

# 4. 공통 마무리 C (A·B 둘 다 여기로)

## C1. 증거 기준 — 무엇을 봐야 '진짜'라고 느끼는가

소유자가 주변에 이 서비스를 설명할 때마다 **첫 질문이 일관되게 "뭘 보고 판단하냐"**였고, **DM을 보느냐**를 물었으며, 좋아요·댓글을 본다고 답하면 **눈에 띄게 실망**했다. 반복적이고, 일관되고, 우리가 유도하지 않은 자발적 반응이다.

**이게 사실이라면 신뢰도 상한이 구조적이다** — 사람들의 멘탈 모델에서 '증거'는 DM인데 우리는 그걸 볼 수 없다.

> **⚠️ 이 구간은 인스타그램으로 한정하지 않는다.** 알아내려는 것이 *"이 사람이 무엇을 진짜 증거로 치는가"*이기 때문이다. 인스타로 좁히면 **DM·카톡·통화기록·오프라인 목격 같은 답이 아예 안 나오고, 그게 바로 우리가 확인해야 할 것이다.** 상대가 인스타 밖 얘기를 꺼내면 따라간다.
>
> **의심의 대상은 상대방(썸남·남친)이지 여자 계정이 아니다.** 말로 붙여서 묻는다.

**여는 질문 — 시점을 상대가 직접 고르게 한다**

- **"썸 타면서(연애하면서) '어 좀 이상한데?' 싶었던 순간이 있었어? 언제였어?"**
  - 없다고 하면: *"그럼 주변에서 그런 얘기 들어본 적은? 친구 중에"* → 간접 경험으로 전환한다. 이 구간을 통째로 버리지 않는다

**그 순간을 특정한 뒤에만 아래로 들어간다**

- **"그때 뭘 보고 그렇게 느꼈어?"** ← *증거 위계가 여기서 그대로 나온다. 우리가 후보를 제시하지 않는다*
- **"그러고 나서 확실히 알아보려고 뭐까지 해봤어?"** ← *팔로잉만 봤는지, 게시물 좋아요 목록까지 뒤졌는지, 폰을 봤는지 — **어디까지 파고들 의사가 있는지***
- **"그중에 제일 결정적이었던 게 뭐야?"** ← *증거 위계의 최상단*
### 상대가 DM·카톡을 언급했을 때 — 두 갈래로 나뉜다

대부분은 **실제로 못 봤을 것이다.** 그러니 "그건 어떻게 봤어?"를 기본 질문으로 두면 안 된다. 먼저 봤는지부터 확인한다.

- **"그거 실제로 볼 수 있었어?"**
  - **봤다면**: "어떻게 봤어?" / "그게 결정적이었어?"
  - **못 봤다면** (이쪽이 다수일 것): 👇 **아래 질문이 이 구간 전체에서 가장 중요하다**

> ### 🔑 **"그럼 그거 대신 뭘 봤어?"**
>
> DM을 못 보는 상태에서 **실제로 무엇을 대리 증거로 썼는지**가 나온다. **우리가 그 자리를 대체할 수 있는지를 결정하는 답이다.**
>
> - 좋아요·댓글·태그 → **우리 신호 집합과 겹친다. 대체 가능**
> - 팔로잉 목록·프로필 분위기 → 겹친다
> - "폰을 몰래 봤다" → 우리가 못 하는 영역
> - "그냥 참았다 / 아무것도 안 했다" → 대리 증거 자체가 없다. **미충족 상태로 방치된다는 뜻이고, 이건 기회다**
>
> 이어서: **"그걸로 충분했어?"** / **"결국 어떻게 결론 내렸어?"**

**왜 이 질문이 핵심인가**: *"DM이 증거다"*는 거의 누구나 말한다. 그건 **이상**이다. 우리가 알아야 하는 건 **DM을 못 볼 때 실제로 뭘 대신 썼는가**이고, 그게 우리 제품이 대체 가능한지를 결정한다. **이상과 실질 기준은 다르다.**

### 마지막 — 비유도에서 안 나온 것만 유도로 확인한다

> **⚠️ 순서가 전부다.** 아래는 **위의 비유도 답변을 전부 받아낸 뒤에만** 묻는다. 규칙 3(우리 어휘를 먼저 꺼내지 않는다) 위반이 아니다 — 그 규칙의 취지는 *답을 우리 프레임으로 오염시키지 말라*는 것이고, **비유도 답을 이미 확보한 뒤에는 오염될 것이 없다.**
>
> **그리고 물어야만 한다.** 안 물으면 "DM을 언급하지 않았다"가 *중요하지 않아서*인지 *그냥 생각이 안 나서*인지 구분할 수 없고, 그러면 이 구간의 결론이 나오지 않는다.

- (DM·카톡이 안 나왔다면) **"혹시 카톡이나 DM 같은 건 생각 안 났어?"** ← *반응 자체가 데이터다*
- (좋아요·댓글이 안 나왔다면) **"인스타 좋아요나 댓글 같은 건 봤어? 그건 어떻게 느껴졌어?"**

기록할 때 **비유도(스스로 말함)와 유도(물어봐서 나옴)를 반드시 구분**한다. 둘은 가중치가 다르다.

### 판정 규칙

**비유도 언급과 유도 후 반응을 나눠서 읽는다.** 이전 판본은 "먼저 언급하면 확정"만 적어서 **언급하지 않은 경우를 해석할 수 없었다.**

| 응답 패턴 | 해석 |
|---|---|
| **비유도**로 DM·메신저를 먼저 언급 + 실제로 봤음 | **DM 상한 문제 확정.** 실질 기준이 DM이다 |
| **비유도**로 DM 언급했으나 **못 봤고, 대신 좋아요·댓글·프로필을 썼다** | **가장 유리한 결과.** DM은 이상이고 실질 기준은 우리 신호 집합과 겹친다 |
| 비유도로 DM 언급, 못 봤고, **대리 증거도 없이 참았다** | 미충족 상태로 방치. 상한 문제이자 **동시에 기회** |
| 비유도에 DM 없음 → **유도하니 "아 맞다 그게 제일 중요하지"** | DM이 이상 기준. 다만 평소 사고에는 없다 → 상한 문제 **약함** |
| 비유도에 DM 없음 → **유도해도 "굳이? 인스타로도 알지"** | **상한 문제 없음.** 우리 신호 집합이 그들의 기준과 부합 |
| "그냥 느낌" / 프로필 분위기만 | 정확도 요구 자체가 낮음 → 재미 포지션과 정합 |

**이 구간의 결과가 "진지한 유료 판정 도구"와 "저가 바이럴" 중 어느 쪽이 가능한지를 가른다.** 캔버스 ③(UVP)과 ⑥(수익원)이 여기 달려 있다.

## C2. 지불 의사와 산출물 — 과거 행동만

**미래 의향을 묻지 않고 지불 의사를 재는 유일한 방법은 과거 지출이다.**

- **"연애 관련해서 돈 써본 적 있어? 타로나 사주, 궁합, 연애상담 같은 거."**
- 있다면:
  - **"얼마 냈어?"** ← *가격 앵커*
  - "그때 뭐가 제일 궁금해서 봤어?"
  - "보고 나서 어땠어? 도움 됐어?"
  - **"결과 같은 거 받았어? 캡처해뒀어? 지금도 갖고 있어?"** ← *보고서 파일 가설 검증*
  - "그 결과 누구한테 보여줬어?" ← *공유 루프*
- 없다면: "돈 낼 만큼은 아니었어? 아니면 그냥 그런 게 있는 줄 몰랐어?"

> **왜 타로·사주인가**: 이 불안에 대해 **실제로 돈이 도는 유일한 비교군**이다. 2~5만원대 지출 이력이 확인되면, 현행 990~1,990원이 그 카테고리와 완전히 다른 층위라는 캔버스 ⑥의 관측이 지지된다.

## C3. 닫기

- "내가 안 물어본 것 중에 얘기하고 싶은 거 있어?"
- **"이런 얘기 편하게 할 만한 친구 한 명만 소개해줄 수 있어?"** ← *다음 표본 확보. 이게 인터뷰를 지속 가능하게 만든다*

# 6. 종합 판정 기준 (인터뷰 시작 전에 고정)

라운드가 끝난 뒤 기준을 바꾸면 그건 검증이 아니라 사후 해석이다.

| 결론 | 조건 |
|---|---|
| **H-B 채택** | 6명 중 4명 이상이 특정 인물 1~5명을 지목, 그중 과반이 우리가 묻기 전에 먼저 언급 |
| **H-A 채택** | 6명 중 4명 이상이 "모른다 / 떠오르는 사람 없다" |
| **H-C 채택** | **A 집단(썸) 3명과 B 집단(연애) 3명의 판정이 집단별로 갈린다** (예: 썸 = H-A 쪽, 연애 = H-B 쪽) |
| **세그먼트 미성립** | 6명이 서로 완전히 다른 이야기를 한다 → 세그먼트가 아직 존재하지 않는다는 결론이고, 이것도 유효한 결과다 |
| **DM 상한 확정 (나쁜 결과)** | 4명 이상이 **비유도로** DM을 언급하고 **실제로 봤으며** 그게 결정적이었다 → 실질 기준이 DM이다. 진지한 판정 도구 포지션은 약속을 지킬 수 없다 |
| **DM 상한 없음 (좋은 결과)** | 4명 이상이 **DM을 못 봤고, 대신 좋아요·댓글·프로필을 대리 증거로 썼다** → DM은 이상일 뿐 실질 기준은 **우리 신호 집합과 겹친다** |
| **판정 불가** | 비유도에서 DM이 안 나왔는데 **유도도 하지 않은 경우.** 이건 결과가 아니라 실행 실패다 — C1의 마지막 유도 질문을 빠뜨리면 이 칸에 빠진다 |
| **대안 부재 확정 (썸)** | **A 집단 3명 중 2명 이상**이 "사귀는 것도 아닌데 못 물어본다"류로 답한다 |
| **지불 의사 신호** | 3명 이상이 연애 관련 실제 지출 이력 보유. 금액 분포를 가격 앵커로 기록 |
| **썸 세그먼트 도달 불가** | **A 집단 3명 중 2명 이상이 맞팔이 아니다** — 이 경우 나머지 결과와 무관하게 썸 타겟은 기술적으로 불가능하다 |

# 부록 — 이탈자 익명 인앱 설문 (연기)

**상태: 연기.** 로그인 이전 배포 이후에 재검토한다. 아래는 그때 쓰기 위한 설계 보존이다.

## 왜 개인 연락이 아니라 설문인가

이 서비스는 사용 행위 자체가 떳떳하지 못한 종류다. 남자친구의 인스타그램 아이디를 입력했다는 사실을 **운영자 개인이 알고 있고 그걸 근거로 연락했다**는 것은 유저 입장에서 감시당했다는 신호다.

**결정적인 이유가 하나 더 있다.** 랜딩이 파는 약속이 *"조회 흔적도, 알림도 남지 않습니다"*인데, 운영자가 개인 연락을 하는 순간 **"아무도 모른다"는 약속의 정서적 신뢰가 무너진다.** 제품의 핵심 소구를 스스로 훼손하면서 얻는 데이터는 값이 없다.

## 왜 지금은 만들지 않는가

1. **그 화면은 이미 지우기로 했다.** [승인된 방향](./2026-08-05-anonymous-preflight-ux-design.md)은 로그인을 결제 클릭 시점으로 옮긴다. **삭제하기로 결정한 관문을 계측하는 셈**이다
2. **왜 안 하는지는 이미 강한 가설이 있고, 수정은 하위 사유와 무관하게 같다.** 신원 노출 부담이든 무료 기대든 답은 "가치를 준 다음에 로그인을 요구한다"로 수렴한다
3. **더 싸고 확실한 측정이 있다.** 배포 전후로 `target_submitted → plan_viewed` 전환을 비교하면 **응답률에 의존하지 않고 전수로** 잰다

## 띄울 수 있는 자리 (참고)

| 지점 | 이탈 | 띄울 수 있나 |
|---|---:|---|
| 로그인 모달 | 81명 | ✅ 모달은 우리 UI. `closeLogin`(`components/landing-page.tsx:88`)이 닫는 순간을 잡는다. 모달 열 때 history entry를 push하면 뒤로가기 이탈까지 잡힌다 |
| 플랜 화면 | 15명 | ❌ 대부분 탭을 닫거나 앱을 떠난다. `beforeunload`는 모바일에서 신뢰할 수 없다 |

## 설계 원칙

| 원칙 | 이유 |
|---|---|
| **자동화된 것으로 읽혀야 한다** | "우리가 당신을 봤다"가 아니라 "시스템이 모두에게 묻는다"로 느껴져야 한다 |
| 개인 식별 언급 금지 | "지난주에 들어오셨는데"류 표현 금지. 그 한 줄이 감시 신호다 |
| 언제든 닫힌다 | 강제하면 이탈 지점이 하나 더 생긴다 |
| 한 문항 | 두 문항부터 응답률이 급락한다 |
| 보상 없음 | 기프티콘은 응답 편향을, 무료 이용권은 지불 의사 데이터 오염을 만든다 |

## 문항 (로그인 이전 배포 후에는 결제 지점으로 옮기고 문항도 가격·신뢰 쪽으로 바꾼다)

> **어떤 점이 망설여지셨어요?** (익명이고, 답 안 하셔도 됩니다)

| 선택지 | 검증하는 것 |
|---|---|
| 로그인하기가 부담돼서 | 신원 노출 부담 |
| 결과가 어떻게 나올지 몰라서 | 샘플 공개 가설 |
| 무료인 줄 알았어서 | 유입 문구의 무료 기대 |
| 그냥 둘러보는 중이었어서 | 재미·호기심 세그먼트 |
| 기타 (주관식 한 줄) | 예상 밖 |

**선택지 순서를 무작위화**한다. 고정 순서는 첫 항목에 응답이 몰린다. 기타 응답은 전부 원문 그대로 보관한다.
