## 안전한 환경설정 관측

두 역할 모두 legacy freeze mode는 DRAIN-AND-BLOCK이고 legacy producer frozen·drained·target blocked·queue pause confirmed 및 public freeze 설정은 true였다. 이는 분리된 legacy 경로 설정이다. 현재 운영 큐 RUNNING·스케줄러 ENABLED 관측과 함께 기록하며 옛 PAUSED 상태로 되돌리는 근거로 사용하지 않는다.

preflight 역할의 `PREFLIGHT_TASKS_ENABLED`는 true다. paid 역할의 `ANALYSIS_V2_WORKER_ENABLED`, `ANALYSIS_V2_RECOVERY_ENABLED`, `ANALYSIS_V2_TASKS_ENABLED`는 true다. 역할에 해당하지 않는 gate나 설정이 없는 key는 JSON에 false 또는 null 그대로 기록했으며 전체 서비스 비활성화로 해석하지 않았다.

두 역할의 Vertex allowlist 관측은 다음과 같다.

- `ANALYSIS_V2_VERTEX_AI_COST_OPTIMIZATION_V212_ROLLOUT`: TEST_ENTITLEMENT.
- `VERTEX_AI_BUDGET_GUARD_ENABLED`: true. `VERTEX_AI_BUDGET_STORE`: SUPABASE.
- 일/주문/실행 budget 세 값은 모두 존재하고 각 key의 해시는 두 역할에서 일치한다. 실제 값은 기록하지 않았다.
- `VERTEX_AI_MODEL`, `VERTEX_AI_COST_OPTIMIZED`, `VERTEX_AI_ANALYSIS_CONCURRENCY`는 명시 설정을 관측하지 못했다. null은 false나 0을 뜻하지 않는다.

이 관측은 runtime 설정 확인이다. 실제 label 기반 recall·비용 절감·route/unknown-usage 품질 gate를 통과했다는 증거가 아니다.

## 실행한 읽기 명령과 남은 범위

실제 selector 값은 root 파일과 native 응답에서 메모리로 주입했다. 아래는 실행한 command shape이며 placeholder를 그대로 실행하는 운영 명령이 아니다. 모든 조회에는 `--quiet`를 사용했고, 네이티브 응답을 반환하는 명령에는 `--format=json`을 사용했다.

```text
git worktree list --porcelain
gcloud run services list --platform managed --project <root-project>
gcloud run services describe <role-service> --region <service-region> --project <root-project>
gcloud run revisions describe <ready-revision> --region <service-region> --project <root-project>
gcloud tasks queues list --location <root-location> --project <root-project>
gcloud tasks queues describe <runtime-queue> --location <queue-location> --project <root-project>
gcloud scheduler jobs list --location <root-location> --project <root-project>
gcloud builds describe <approved-build> --region global --project <root-project>
gcloud builds describe <approved-build> --region <worker-region> --project <root-project>
```

native worker·queue·scheduler·승인 build 조회의 현재 blocker는 없다. 정확한 미검증 범위는 다음과 같다.

1. 이번 관측에서는 generation-pinned source archive를 내려받아 Git과 byte 단위로 다시 비교하지 않았다. 과거 승인 receipt의 archive 증명과 현재 동일 revision·image·성공 build의 연속성을 확인했다.
2. task별 target/OIDC·queue backlog·실제 사용자 분석 성공 여부를 확인하지 않았다. raw task·사용자 event·provider 실행으로 범위를 넓히지 않았다.
3. 공개 웹 readiness와 Vercel native 배포의 최신 source는 W02의 다른 담당 관측과 합쳐야 한다. 웹 source가 승인 worker source보다 새롭다는 이유만으로 worker 재배포를 권고하지 않는다.
4. Vertex의 실제 품질 증거와 승격 여부는 [W04의 별도 결론](2026-10-03-w00-w04-evidence.ko.md)을 따른다.
