### 정확한 보류 사유와 재개 조건

1. **품질 blocker:** 검증 가능한 실제 v2.12 high-risk true-positive/actual-high-risk count, 비교 baseline count와 label 기준·표본 범위·관측일·출처 hash가 없다. 동일 비교 범위의 route mix, unknown usage와 비용 aggregate도 필요하다. 현재 fixture status는 계속 `unverified_fixture`다.
2. **운영 재검토 경계:** W02에서 현행 rollout/budget guard와 승인 artifact 관계의 관측을 확보했다. 원격 migration provenance는 W05 결과와 연결하고, source archive의 새 byte 검증 여부 및 일부 annotation 차이는 W02의 정확한 증거 범위를 유지한다. 이를 품질 blocker의 대체 근거로 사용하지 않는다.
3. **사용자 검증 경계:** 사용자의 실제 계정 테스트는 미실행이다. 일반 운영 readiness 또는 35개 단위 테스트로 실계정 성공을 대체할 수 없다.
4. **재개:** 승인된 retained evidence가 있으면 원시 계정/사용자 payload를 복사하지 않는 검증 가능한 집계·provenance부터 평가한다. 없다면 사용자가 승인한 canary/실테스트 결과가 생긴 뒤 검토한다. 기준을 통과한 gate와 현재 운영·migration·인증정보 후속 조치 확인을 갖춘 별도 승격 검토 전에는 rollout/traffic/migration을 변경하지 않는다.

따라서 현재 적절한 종료 상태는 **품질 증거 대기, 코드·fixture·rollout 변경 없음**이다. 과거의 별도 `20260904090000` migration을 새로 만들거나, 일반 운영 활성화를 이유로 gate를 완화하지 않는다.
